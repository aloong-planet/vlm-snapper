# VLMSnapper v1 core features

VLMSnapper requires macOS 14.4 or later and provides screenshot-based text extraction and translation.

## Menu-bar application

VLMSnapper runs in the menu bar without a Dock icon. A left click opens or closes the 300-point panel directly below the menu bar; the panel remains inside the current screen horizontally and closes when the user clicks outside it. Its compact arrow points back to the status item without covering the menu bar. A right click opens a native context menu containing only Quit VLMSnapper. The left-click panel presents real Provider readiness, the active capture shortcut, a white raised Capture button with centered dark text and a gray shortcut, an available-update notice, and up to five most recent records with screenshot thumbnails, operation/time, and terminal status, then provides Provider and Settings footer buttons leading directly to Provider configuration and General Settings in the same management center. Fewer than five records are shown as-is without placeholder rows; the panel grows vertically with the same row styling and width. This limit does not truncate the full management-center history list. Only the destination page remains selected in the sidebar. Manual update checking stays in General Settings. Quit and Command-Q behave consistently. Permission recovery and storage/privacy panels do not block quitting; canceling an unsaved-result confirmation keeps both the application and the original panel open. Provider configuration stays within Settings Center rather than a separate panel. Opening the application again brings the existing instance forward rather than creating another menu-bar icon.

The application provides a localized native macOS menu bar. Its Edit menu includes Undo/Redo, clipboard commands, Find, spelling and grammar, substitutions, transformations, speech, Dictation, and Emoji & Symbols, available according to the focused editor. In the Provider API-key field, Command-V, Edit Paste and the native context-menu Paste replace the current selection and remove at most one trailing line ending from that pasted text. Other characters and the clipboard remain unchanged; other editors keep their standard Paste behavior.

## First-run setup and recovery

The onboarding checklist groups its brand mark and introduction above three readiness cards with icon tiles and status badges. A tinted panel explains what remains or confirms readiness. The privacy note sits on the left of the footer, with Finish Later and Start Using grouped on the right. Longer content can scroll without being clipped.

The onboarding window separates screen-capture permission, online Provider configuration, and storage/privacy details. A user may finish later, but capture remains unavailable until both permission and one Provider/model are usable. Its Provider action opens the Provider page in Settings Center; choosing a model after successful validation returns automatically, while closing Settings Center early returns with the actual incomplete state. That page manages DeepSeek, OpenAI, and Gemini through one-open inline cards instead of a separate setup sheet. The Provider content stays centered at a readable maximum width; credential and model controls sit side by side when space permits and stack without clipping in a narrow window. Each card keeps its secure API-key field, model picker, refresh, current-Provider action, and confirmed removal together. Entering a new key makes validation available. Once replacement is accepted, the old key and configuration cannot be restored after failure. If local storage prevents accepting replacement, no validation request is sent; the original saved configuration is preserved and a local storage error is shown. Validated keys are stored in Apple Keychain, model lists come from the account, and a rejected key remains distinct from a temporary Provider failure. Provider controls are read-only during an active model request. Permission recovery distinguishes first request, denied/revoked access, Settings, and restart-required states. The macOS permission explanation identifies VLMSnapper and states that screen access is used to capture a selected area for text extraction or translation in the supported interface language.

Typing or pasting a changed API key enables validation while the field still has focus. Empty values, remaining line breaks, or values above 4096 UTF-8 bytes cannot be submitted; a local hint explains the problem. Spaces, tabs and Unicode remain unchanged. Clearing disables validation without removing the saved configuration. Returning the text to its exact loaded value makes it unchanged again, so Return does not revalidate it. Showing or hiding the key preserves focus and selection.

Accessibility input updates the same draft and validation state in both concealed and revealed modes. It cannot edit a disabled, read-only or hidden field, and changing text alone does not submit the key.

Settings Center refreshes keep the displayed input and validation controls consistent. Return and Validate share one submission; repeated activation while a Provider is validating does not start another. While one Provider is being configured or recovered, another card may hold an editable draft, but validation, model changes, refresh, changing the current Provider and removal remain unavailable. After the active work ends, validation becomes available only if that draft is still changed, nonempty and valid. Switching cards or closing discards an unsubmitted draft. An already-submitted validation continues for its original Provider; returning shows its pending or terminal state. A failed candidate remains available for correction until it is edited, cleared, removed or the application exits. While a card's saved key is loading, its credential controls are unavailable.

During screen freezing, region selection or a model request, all Provider configuration controls are read-only. Recovery waits for that activity to finish before starting. Conversely, capture requested during Provider credential work opens Settings Center at the active Provider instead of freezing a screen or creating a selection. Try Again is also unavailable and does not send a request or change history. The capture toolbar therefore has no configuration-in-progress state.

If a saved key is missing, its stale Provider configuration and current selection are cleared. If the saved configuration cannot be read, the card shows a local secure-storage error and stays read-only; collapse and reopen the card to retry. When a saved key survives an interrupted configuration update, opening the card or restarting the app reloads its complete model list. The card shows Recovering and stays read-only until recovery finishes. A stored key is not shown as usable before its model configuration is recovered. Exiting cancels pending credential work and does not resubmit a lost candidate on the next launch.

Refreshing a model list keeps the configured key, cached models, selection and footer actions visible. The fixed-size Refresh button shows progress; conflicting actions stay disabled in place without adding a lock banner. Ordinary refresh failures preserve the saved configuration and replace the existing model-help text with an inline error and manual retry. Returning to the card shows the same job's progress or result. A successful refresh preserves the selected model if it still exists; otherwise a model must be chosen explicitly.

The model selector fills the available row beside Refresh, including in a narrow stacked card. The API Key heading is secondary text; the current Provider is marked in green and Remove Configuration is a red text action.

Provider card headers distinguish DeepSeek with DS, OpenAI with OA, and Gemini with G beside their full names. These centered gray identity marks sit on rounded blue tiles adapted to light and dark appearance and stay unchanged across interface languages.

## Frozen-frame capture

The global capture shortcut defaults to `⌥⇧S` and can be changed through a key-recording control in General Settings. A replacement is registered before the previous shortcut is released; invalid or conflicting input leaves the old shortcut active and shows a localized explanation. The panel's Capture Screen button enters the same workflow. Missing Provider or permission readiness brings the centered onboarding window to the front. When capture is ready, the frozen image excludes VLMSnapper's menu, onboarding, history, settings, result, and selection windows. Open VLMSnapper windows are hidden only after the new selection view appears; a capture failure leaves them unchanged.

Triggering capture freezes every available display at that instant. Selection panels show only those frozen images, so videos and animation cannot advance between trigger and crop. On Retina displays, the frozen preview and cropped PNG retain the display's native pixel detail instead of using its lower logical point resolution. A rectangular selection is mapped into display-local physical pixels and cropped into the original sRGB PNG. Escape, cancel, or retriggering before a model request discards the in-memory capture without creating history.

During selection, a disconnected or sleeping display, or a change to its resolution, scale, rotation or position, retires that display's frozen selection view without waiting for mouse-up. Other unchanged frozen displays remain available; newly connected displays become selectable only after a new capture. If none remain, selection ends without creating history. A completed crop is not discarded by later display changes.

## Extract and translate operations

The compact toolbar stays 4 px from the selection and offers Extract Text, Translate, a searchable target-language picker, the current Provider/model, and cancel. The language list uses stable standard codes, keeps 11 common languages first, excludes Traditional Chinese and arbitrary manual values, and remembers the last choice.

Screenshot operations require an image-capable model. Appearing in the account's model list alone does not establish image support; if the selected model cannot process images, choose a supported model explicitly. VLMSnapper does not switch models automatically.

Each accepted, user-triggered Extract, Translate, or Retry creates exactly one request to the currently selected online multimodal model. Translate sends the original PNG and returns both recognized source text and translated text. There is no separate local text-recognition step or second translation request. DeepSeek processing may continue without visible text, but private reasoning is never displayed or saved and the 90-second total deadline remains in force. A failure stops the operation and shows its reason; there is no automatic retry.

The result workspace keeps the original screenshot beside streamed results. It comes forward when first opened or explicitly requested, then behaves as a normal window that may move behind other applications; streaming refreshes do not steal focus. Triggering capture from a terminal, fully saved workspace preserves that workspace until the frozen selection overlay is ready, then hides it; a capture failure leaves the workspace available. An active request or unsaved result stays protected in front. Extract and Translate slots are independent, reuse the same original PNG, and never start merely because the user switches tabs. Try Again reuses the current screenshot-operation history record, atomically replaces its text and bilingual correspondence only after a successful rerun, and preserves the previous saved result after a failed or canceled rerun. Closing an active request cancels and persists it. A result that could not be saved remains copyable and requires explicit confirmation before discard.

Translations show equal-width source and translation columns in both the result workspace and history detail. Corresponding passages appear progressively in the same request, without waiting for the entire source first. Sentences remain continuous within paragraphs; headings and list items retain their logical grouping, not the screenshot's exact typography or geometry. Long text and links wrap within their own column as the window changes or content arrives; timing and token usage remain below both columns. Hovering, clicking or selecting text highlights its corresponding passage in both columns; selection takes priority over hover, including selections spanning several passages. Streaming appends preserve the current selection. Clicking blank space clears it, and changing records or retrying clears old correspondence. Each column has a copy icon with a tooltip and brief confirmation; it copies only that column's current text and paragraph/list structure, and is disabled when empty. Extraction stays single-column. Earlier history without correspondence remains readable, searchable and copyable in two columns, without guessed highlights or an automatic network request. Displaying, selecting and copying result text does not open embedded links or load remote content.

## Local history and screenshots

The operation filter shows its three choices directly, without an extra visible heading; its accessible name remains available to assistive technology.

Before a screenshot request uploads, VLMSnapper saves the original screenshot and prepares its history record. If local saving fails, it does not upload. Screenshots are stored by year-month in the VLMSnapper folder inside Pictures, with timestamp-based names; captures made in the same second do not overwrite each other.

The management center provides a light navigation surface and a compact gray All / Extract Text / Translate group. A Provider selector sits between that group and source/translation search; its choices come from local history, including Providers that are no longer configured. These conditions combine, and Pinned further restricts the same query to pinned records. There is no advanced filter panel. The Chinese history label for extraction is “提取”.

The management center initially fills the available screen as an ordinary window, preserving the menu bar and window controls without entering a fullscreen Space, and retains user resizing and positioning across page changes and temporary hiding. Its 180-point sidebar groups Library and Settings Center, shows history, pinned and supported-Provider counts, and omits the current-Provider summary card. The 260-point record list leaves more room for the bordered detail card with original screenshots, model information, latency, usage, delete, and clear-history actions. Row types are blue; completed states are green, canceled states orange, and failed or interrupted states red, with text labels retained. Dates remain region-formatted and right-aligned, wrapping when necessary. Records use inset rounded rows with single-line titles and summaries. Summaries prefer the translation, then original text, then status; pin controls remain in the detail card rather than the record row. Selected rows retain a blue background while hovered; unselected rows highlight gray on hover, without selection borders. Light and dark appearances use consistent row colors independent of the system accent. The header, list footer, and detail content remain visible at the supported minimum window size.

Clicking a record or tabbing into the History or Pinned list enables Up/Down navigation through the currently visible, filtered records. The detail follows the selection and the selected row scrolls into view. Navigation stops at either end instead of wrapping; single-record and empty lists cannot advance. The selected background remains the visual cue without an outer focus ring. Search, filters and detail text retain their own arrow-key behavior while focused; image refreshes do not take focus away from the list. Arrow navigation does not retry, change pins, or open a new window.

History results stay in the management-center detail pane. Retrying never adds a Retry heading or repeated Provider/model above the text, and a successful retry does not leave a separate Done message. Feedback for running, failed, canceled, and unsaved attempts remains available. Closing a result created by a new capture does not open the list.

The screenshot is a compact, centered, proportional thumbnail, up to 100 points tall, inside a full-width rounded background with a subtle border and no vertical gap around the image. A light divider separates the screenshot from the text; translations use equal-width source and target columns with aligned header and body dividers. Extraction entries do not show an empty translation section. Clicking an available image opens an enlarged preview in the management center; it initially fits the window and can switch to 100% actual size. Scrolling over the preview zooms around the pointer without a modifier key or scrolling the history behind it; trackpad momentum does not continue zooming. Drag the enlarged image to pan, or use its scrollbars. Zoom stops at 800% and at the smaller of 5% or the fit-to-window scale. After manual zoom, Fit to window restores the initial view. Close, Escape, or clicking the backdrop outside the preview within the management center returns to the same history detail without activating anything underneath; reopening starts fitted again. Clicking inside the preview, dragging the image, or clicking another window does not dismiss it. An unavailable original cannot be enlarged.

The history detail header has adjacent 30-point Retry, Pin, and Delete icon buttons without extra gaps. Hovering over the clockwise arrow shows Retry. When the original screenshot and current Provider/model are available, Retry runs the record's original operation and target language and updates that same history entry only after the complete result is successfully saved. It does not add another entry or copy the screenshot. The original creation time and pin choice are preserved, including a pin change made while the request is running. Progress and results stay in the right-hand detail without opening another window. Repeated clicks do not send duplicate requests; conflicting Provider work and unavailable screenshots disable Retry. Failed or canceled retries leave the saved entry unchanged. Closing or hiding the management center does not discard the retry; returning to its source record shows the retained progress or result. If the result could not be saved, Retry Save updates the same entry locally without another Provider request. A deleted target is reported as unavailable and is never recreated by retry. While running or awaiting a successful save, history deletion and Clear History are unavailable, and cleanup waits. Exiting asks before discarding an unsaved result. Existing duplicate entries are not automatically merged or deleted.

Extraction records with saved text also have a Translate original icon immediately before Retry, in both History and Pinned. Clicking it sends only that saved text to the current Provider/model using the current target language, even if the screenshot is unavailable. The full original appears immediately on the left while its translation streams on the right, with linked passage highlighting and separate copy icons. Complete results convert the same entry to translation without adding an entry or image; creation time and pin choice remain unchanged. Failure or cancellation preserves the extraction. An unsaved complete translation remains available for local Retry Save without another request. Conflicting work and deletion are blocked while it runs or awaits saving; closing the management center does not lose it. On success, an Extract filter switches to All only if this entry is still selected; Provider, search and Pinned conditions remain in force, and another selected entry is not replaced. The Translate original icon then disappears. The existing Retry button still rereads the original screenshot and performs screenshot translation with the saved target language; it is disabled if the image is unavailable.

Queries stay in place while visiting settings or temporarily hiding the window for capture; closing and reopening resets them. A still-matching selection is retained, otherwise the first matching record is selected, and an empty result clears the detail. Starting capture keeps the management center available until the new frozen selection overlay is visible, then hides it behind that overlay; a capture failure leaves it unchanged. A single click selects a history record; double clicking adds no action and does not open another window, contact the Provider, or create history. If the original screenshot is no longer available, the saved text remains readable but screenshot Retry is unavailable; Translate original remains available for extraction text. Deletion removes only the application's original, unmodified screenshot; a replacement saved at the same location is retained.

Opening or switching history records leaves the image area blank until its original is ready, without loading text or a spinner. Refreshing or retrying the same record retains its validated image during reading. Only a failed read or validation shows the unavailable notice, while saved text stays readable. Switching never shows another record's image, and an older read cannot overwrite the latest selection. Selecting again can recover an image that becomes available.

Unpinned history defaults to 30 days, with 7, 30, 60, 90, or 180 days available. Cleanup runs once at primary startup and is checked during the application lifetime, never more than once per 24 hours. Shortening retention shows the affected count before permanent deletion. Partial failures continue and remain visible for retry.

## Settings, diagnostics, and updates

General Settings includes interface language, capture shortcut, login at launch, update checking, history retention, and diagnostics export. The interface supports Simplified Chinese and English; changing it requires restart. Sanitized allowlisted diagnostics are retained for seven days and exported as gzip without API keys, authorization headers, prompts, screenshots, recognized text, or response bodies.

When automatic checking is enabled, VLMSnapper checks for updates every six hours. It never automatically downloads an update. An available version is shown in the menu and Settings; the user chooses when to download. The interface reports download and installation progress, and immediate installation first closes active work safely.

Updates use the same three-part version shown for the application, without a separately increasing build number. An identical version is not offered as a new update.

The automatic-check explanation appears only beneath its switch, not again beneath the current-version or checking status. These single-line statuses use compact spacing without extra space for a description. Available-update, download, installation, and failure details retain their spacing and remain visible.
