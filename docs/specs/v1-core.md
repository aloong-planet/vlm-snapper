# VLMSnapper v1 核心规格

状态：历史页面的简化筛选与布局已确认；重试统一更新原记录已接入实现，完整验收及下列 Pending 项尚未完成。不代表全功能已验收。DeepSeek 发布就绪仍受本文 Pending 项约束。

## Problem

macOS 用户经常需要从屏幕局部内容中提取文字或获得翻译。现有工具通常依赖传统 OCR 后再翻译，或者拥有与任务无关的标注能力。VLMSnapper v1 要提供一条短、可预测且资源占用较小的路径：冻结快捷键触发瞬间的屏幕、选择矩形区域、保存原始 PNG，并由用户显式选择“提取文字”或“翻译”，将同一张原始截图直接交给在线视觉模型。

产品必须使网络发送、落盘、重试和清理行为对用户可理解且可控制。任何失败不得隐式重试、切换 Provider、改图或用残缺结果冒充成功。

## Solution

VLMSnapper 是原生 macOS 14.4+ 菜单栏应用。v1 接入 OpenAI、Gemini 和 DeepSeek 官方接口，通过统一 Provider 契约获取模型列表、发送图片请求、消费流式事件并归一化错误。应用不在 Dock 或 `⌘Tab` 中显示；菜单栏面板是日常第一入口，统一管理中心承载历史与设置。Provider 的凭据、模型和当前使用状态直接在设置中心的 Provider 页面管理，不再打开独立配置面板。

截图快捷键或菜单栏按钮触发时，应用保持现有界面可见并从同一份 ScreenCaptureKit 内容快照中排除 VLMSnapper 自身，先冻结所有可用显示器的当前帧，再原子显示不透明选区遮罩并把已知的 VLMSnapper 来源界面退到后台。用户确认选区后可在紧贴选区的操作栏中选择操作、目标语言和当前 Provider/模型。新操作首次执行前，应用原子保存原始 PNG 并建立可恢复的历史记录；只有本地持久化成功且请求体未超过 Provider 限制，才允许上传。既有记录重试使用该记录已经持久化的原图和身份，遵循 v1-core::REQ-002 的统一重试规则。

文字提取使用一次多模态请求返回结构化 Markdown。翻译也使用一次多模态请求，直接从截图提取原文并返回原文与译文，不依赖已有提取结果。结果窗口保留原图、操作切换、只读结果、复制、取消、手动重试和重新执行能力。

## User Stories

### 1. 启动与单实例

- 作为用户，我启动 VLMSnapper 时，每个 macOS 用户只能有一个主实例负责菜单栏、全局快捷键、历史、清理和更新。
- 第二次启动只唤醒主实例：有活动结果时将其带到前台，否则打开菜单栏面板，然后退出自身。
- 关闭普通窗口只隐藏窗口，不退出应用；状态项右键菜单的“退出 VLMSnapper”或窗口激活时的 `⌘Q` 才退出。
- 左键点击状态项打开或关闭菜单栏面板；面板宽 300pt，完整位于菜单栏下方，水平方向限制在当前屏幕可见区域内，顶部使用 8×4pt 小箭头指向状态项，点击面板和状态项之外的区域立即关闭。截图按钮使用白色浮起表面和弱边框，不在悬停时位移，标题保持几何居中并使用深色文字，右侧快捷键使用 12pt 灰色文字。右键显示只含“退出 VLMSnapper”的原生菜单。主面板按确认原型显示 Provider 就绪状态、截图与当前快捷键、仅在新版本可用时出现的更新提示、最多五条带缩略图/操作时间/终态的真实最近记录，以及 Provider 和 Settings 双列入口，不重复放置退出或手动检查更新。最近记录不足五条时按实际数量展示，不补空行；面板沿用现有宽度和行样式并随内容增高，管理中心完整历史列表不受此数量限制。权限恢复或存储与隐私附着面板打开时也必须进入相同的正常退出流程，不能被 modal 状态静默取消；Provider 配置位于管理中心内，不再使用独立附着面板。两列分别打开同一个管理中心的 Provider 配置页和通用设置页，跳转后的选中态遵循 v1-core::US-001/AC-19。
- 应用安装本地化的原生 macOS 主菜单。完整 Edit 菜单使用 AppKit responder chain 提供 Undo/Redo、剪贴板、Find、Spelling & Grammar、Substitutions、Transformations、Speech、Dictation 与 Emoji & Symbols。Provider API Key 的标准 Paste 动作允许窄适配：Command-V、Edit 菜单和字段上下文菜单使用同一处理，只移除本次粘贴末尾至多一个 CRLF、LF 或 CR，再通过系统安全编辑器插入当前选区。不替换安全编辑器、不新增快捷键旁路、不修改系统剪贴板；其他字段继续使用原生 responder chain。

### 2. 首次引导与权限

- 首次引导同时呈现屏幕录制权限、Provider/当前模型和存储与隐私三个项目。
- 引导页使用品牌标记与标题组成的介绍区、带图标底板和状态徽章的三项准备卡片、带标题和说明的浅色状态提示区；底部左侧是隐私说明，右侧并列“稍后完成”和“开始使用”。内容区宽 `900pt`、最小高 `604pt`，内部可读内容最大宽 `760pt`；长文案可滚动，不裁掉操作。原生标题栏由系统提供，不绘制模拟标题栏。
- 前两项是开始使用的必要条件；缺少任一项时按实际缺项说明原因并禁用“开始使用”。“稍后完成”始终可用，存储与隐私说明不作为阻断条件。
- 三个项目的操作按钮使用同一类次要描边样式。存储与隐私详情使用 8 px 圆角的连续扁平表面，按在线处理、本地保存、自动清理、备份与同步分区；只提供关闭，不提供设置跳转、同意复选框或面向用户的实现术语。
- 用户跳过引导后，首次触发截图才请求屏幕录制权限。授权成功提示重启并提供一键重启；拒绝或权限被撤销后只说明原因并提供系统设置入口，不重复弹出系统请求。
- 未配置可用 Provider/当前模型时，截图入口把首次引导窗口带到最前。用户从引导页跳转到设置中心的 Provider 页面，不启动屏幕冻结或系统权限请求；成功验证 API Key 并选择模型后自动返回引导页，只有模型选择完成才算配置完成。用户提前关闭设置中心时也返回引导页，并继续显示真实的未完成状态。

### 3. 截图入口、全局快捷键与屏幕冻结

- 默认快捷键是 `⌥⇧S`，用户可在设置中通过按键录制控件修改。
- 保存快捷键前立即尝试注册；冲突或注册失败时显示具体错误并保留旧快捷键，成功后立即生效。
- 菜单栏面板的“截取屏幕”按钮与全局快捷键进入同一个截图工作流。Provider 未配置或权限未就绪时把首次引导窗口带到最前并显示对应恢复入口；两项就绪时先冻结排除 VLMSnapper 自身的屏幕，选区遮罩显示后再退下来源界面。
- 截图工作流触发瞬间冻结每块显示器的当前帧。视频或动画选择期间继续播放，不影响最终截图；最终截图来自触发时的冻结帧。
- 各显示器独立冻结。捕获失败的屏幕不可选并显示原因，其他成功屏仍可使用；全部捕获失败时退出选区且不创建历史。全局权限问题进入权限恢复流程。冻结后的显示器变化遵循 v1-core::REQ-001。
- 选区只支持矩形，最小为 2 × 2 物理像素。无效选区保持在选择状态供用户调整；`Esc` 或取消退出且不保存。
- 选择开始后的显示器集合与冻结帧生命周期遵循 v1-core::REQ-001。
- 原始 PNG 不包含鼠标指针、选区遮罩、尺寸标签、边框或操作栏；选区中的其他应用、菜单栏、Dock 和系统窗口按冻结帧原样保留。
- Retina 显示器按 ScreenCaptureKit 报告的 point-to-pixel 比例冻结物理像素帧；选区预览按逻辑尺寸显示，但冻结帧和最终 PNG 不降采样到逻辑 point 分辨率。
- 输出固定为 8-bit SDR、sRGB、原始 PNG，不转 JPEG、不缩放、不压缩、不做色彩增强。

#### v1-core::REQ-001 选区中的显示器变化

适用范围：冻结完成至本次选区结束；遵循 ADR-0010，不因补验收改变截图时机。

- v1-core::REQ-001/AC-01：选区期间已冻结显示器断开时立即使该屏不可选并撤下其遮罩、释放其冻结帧，不等待鼠标松开。
- v1-core::REQ-001/AC-02：选区期间显示器分辨率、缩放、旋转或几何布局变化时只使受影响屏幕失效，并取消其当前拖拽，不重新捕获实时画面。
- v1-core::REQ-001/AC-03：已冻结显示器休眠时使其失效；唤醒不恢复本次已经失效的冻结帧。
- v1-core::REQ-001/AC-04：部分屏幕失效后，未变化的成功冻结屏幕仍可继续选择。
- v1-core::REQ-001/AC-05：本次选择开始后新接入的显示器不可选，下一次显式截图才纳入新的冻结集合。
- v1-core::REQ-001/AC-06：冻结完成后和监听注册后均核对完整几何，注册前的异步间隙发生的变化不能遗漏。
- v1-core::REQ-001/AC-07：取消、替换选区和裁切完成后解除旧监听；迟到通知不能撤下或改变新会话的遮罩。
- v1-core::REQ-001/AC-08：全部冻结屏幕失效时结束选区且不创建历史。

> Pending: 真实显示器拔插、显示设置变化、休眠/唤醒和多屏继续选择尚缺当前安装版的硬件验收；注入通知通过不等于硬件通过。

### 4. 选区操作栏

- 确认选区后，截图内容固定不再变化。操作栏默认位于选区左下方 4 px，必要时移动以保持在可用屏幕内，但不移动选区或截图。
- 操作栏使用紧凑布局：3 px 内边距和控件间距、25 px 按钮高度、6 px 圆角。
- 操作栏提供“提取文字”“翻译”、目标语言、当前 Provider/模型和取消。目标语言只在翻译操作中生效。
- 任何模型调用只在用户点击“提取文字”或“翻译”后开始；此之前取消会丢弃内存截图且不创建历史。

### 5. 提取文字与截图翻译

- 提取文字把原始截图直接发给当前多模态模型，返回只读结构化 Markdown；不返回坐标、字体或像素级版面信息。
- 翻译把原始截图直接发给当前多模态模型，在一次请求中按对应片段返回从图片识别的原文及目标语言译文，遵循 v1-core::US-002；不得改成 OCR 后文本翻译或两个模型请求。
- 图片没有文字时，提取结果为空；翻译的原文和译文都为空，不生成图片描述或猜测内容。该操作仍作为成功记录保存并允许重新执行。
- 混合语言图片允许返回多个 BCP-47 源语言。源语言与目标语言相同时仍为成功，不追加第二次请求。
- 目标语言使用完整、可搜索的标准列表，优先展示简体中文、英语、日语、韩语、西班牙语、法语、德语、葡萄牙语、意大利语、俄语和阿拉伯语；不提供繁体中文和手动输入。
- 内置提示词使用英文并带版本号；温度使用 Provider 可表达的最小值或 `0`，推理/思考模式关闭或降至最低，不提供高级参数 UI。
- 每次显式操作恰好产生一个 Provider 请求。失败后不自动重试、切换 Provider/模型、改用非流式请求或降级为其他处理方式。

### 6. 流式返回与结果窗口

- Provider 适配器向应用输出统一事件顺序：提取为文字增量后元数据和完成；翻译为带对应身份的片段增量后元数据和完成，遵循 v1-core::US-002/AC-04。
- 首个有效文字事件超时与事件间停滞超时均为连续 10 秒无有效活动；单次请求总超时为 90 秒。DeepSeek 返回非空 `reasoning_content` 时，只刷新当前无活动计时，不显示、持久化或暴露该内容；可见文字开始前超时仍归类为首字超时，开始后仍归类为事件间停滞。OpenAI 与 Gemini 的活动判定保持不变。
- 应用不主动覆盖 Provider 的最大输出 token。Provider 明确达到输出长度上限、结构不完整或无法可靠解析时，本次操作失败，丢弃未完成流，不把残缺内容保存为正式结果。
- 结果窗口顶部固定“提取文字 / 翻译”切换。切换到已有成功、失败或取消结果只展示内容，不自动请求；从未执行的操作显示显式开始按钮。
- 同一时间全局只允许一个活动模型任务。任务进行时再次触发快捷键，只把当前结果窗口带到前台。
- 结果窗口首次打开或用户再次显式请求时带到前台，随后使用普通窗口层级；用户切换到其他应用后允许进入后台，流式内容刷新不得反复抢回焦点。请求中关闭窗口等同主动取消；新操作保存取消状态，既有记录重试按 v1-core::REQ-002/AC-11 保留原记录。请求完成后关闭只隐藏。
- 结果工作区没有活动模型任务且没有未保存结果时，再次触发截图会先冻结排除 VLMSnapper 自身的当前屏幕，只有新选区遮罩成功显示后才隐藏旧结果窗口；捕获失败时旧工作区保持可用，已经保存的旧结果仍可从历史记录查看。连续触发只接纳一次工作区退让，进入选区后继续沿用原子替换选区的行为。活动请求或未保存结果不会被新截图替换，而是继续把当前结果窗口带到前台。
- 结果只读，可复制 Markdown，不自动写入剪贴板，不提供修改功能。
- 在仍打开的结果工作区点击 Try Again 属于当前结果重跑；从管理中心发起的历史操作重跑只在入口上不同，两者统一遵循 v1-core::REQ-002/AC-03、v1-core::REQ-002/AC-10–13 的记录身份与提交规则。从未执行过的另一操作类型仍属于新操作，不因原图相同而合并记录。

### v1-core::US-002 连续段落的双语对照

作为阅读截图翻译的用户，我希望左右对照原文和译文，选中或悬停一处时定位对应内容，并在处理过程中逐步看到两种文本，而不是等待整篇原文结束。

- v1-core::US-002/AC-01：新结果窗口与历史详情的翻译内容均以等宽双栏展示，左原文、右译文；两个标题与正文共用同一条垂直分界位置。文字提取保持单栏，不增加空译文列。
- v1-core::US-002/AC-02：同一段落的相邻句子连续排版，不逐句换行或增加卡片间距；保留识别出的标题、段落和列表层次，不承诺截图坐标、字体及像素级版面复刻。正文 13pt、段间距 10pt、栏内水平留白 15pt，栏标题 15pt semibold，沿用原生界面的明暗主题。两栏独立按各自宽度换行，长段落、长 URL、窗口变窄和流式追加均不得跨栏覆盖或裁掉正文；整体高度容纳较高一栏，耗时与 Token 信息始终在两栏正文下方。
- v1-core::US-002/AC-03：悬停、点击或原生拖选句子时，两栏对应片段共同高亮；跨句选择高亮所有相交片段。对应关系使用本次结果的稳定片段身份，不能按文本搜索或标点猜配；重复句子、组合字符和双向文字不能串配。选中优先于悬停，清除选区/点击空白清除选中，切换记录或重试清除旧映射。
- v1-core::US-002/AC-04：翻译在同一次模型流中按片段交替输出原文和译文，并在接收可用文本后增量展示；第一片段译文不等全部原文才展示。流式更新不能强行清除当前文本选择或抢占焦点；无文字截图允许空片段集合成功。传输分块不构成固定刷新时延承诺。
- v1-core::US-002/AC-05：原文和译文标题右侧各有 30×30pt 的复制图标按钮，悬停有本地化提示；复制当前该栏已显示的完整文本及段落/列表结构，不混入另一栏或界面标签。空栏禁用，成功有轻量反馈，不自动写剪贴板。
- v1-core::US-002/AC-06：只有完整且通过校验的文本及对应结构才能与历史记录原子提交，重新打开和重建应用后仍可对照高亮。旧历史无对应结构时保留双栏内容、搜索和复制，不伪造句子对应、不自动联网补全。
- v1-core::US-002/AC-07：翻译重试沿用 v1-core::REQ-002/AC-03、AC-10–17 的同记录成功替换及失败保护：文字和对应结构一起替换或一起保留，待保存结果支持双栏复制及本地重试保存，不能混合新旧映射。
- v1-core::US-002/AC-08：历史详情右上角重试、Pin、删除仍为相邻 30×30pt 图标按钮，按钮盒间不额外加空隙；原图缩略图及放大、滚轮缩放行为保持不变。
- v1-core::US-002/AC-09：协议截断、重复片段身份、不合法结构或缺失对应文本时按现有不完整响应失败，不以残缺映射报告成功。取消、失败和切换记录不能把旧片段高亮应用到新结果。
- v1-core::US-002/AC-10：模型文本仅作为本地只读文本内容排版，不解释其中的 HTML、脚本、远程媒体或文件路径，不因展示、选中、复制而加载网络或打开链接。异常及长内容仍受现有请求超时/错误边界约束。

### 7. Provider 配置与模型发现

- v1 只支持 OpenAI、Gemini、DeepSeek 官方端点，不允许自定义 Base URL，不接入本地模型。
- 每个 Provider 独立保存 API Key、完整模型列表缓存和当前模型；应用另有一个全局当前 Provider。
- 设置中心的 Provider 页面使用单开折叠卡片直接展示全部配置与测试操作，不再通过“配置/修改”按钮打开独立面板。显式目标 Provider 优先展开，其次展开全局当前 Provider，否则展开 DeepSeek；切换卡片时只关闭前一张卡片，不改变任何 Provider 配置。
- Provider 内容区居中且最大宽度为 `850pt`；卡片头最小高度为 `54pt`，Provider 标记为 `29×29pt`，API Key 与模型选择字段高 `32pt`。空间足够时 API Key 与模型选择并列，较窄时保持原顺序纵向排列，不裁切或把操作推出窗口。
- Provider 卡片标记按已确认设计使用 DeepSeek `DS`、OpenAI `OA`、Gemini `G`，而不是统一芯片图标。字母为居中的 `10pt`、800 字重；底板圆角 `8pt`。浅色使用灰字 `#8a929d` / 浅蓝底 `#e6efff`，深色使用灰字 `#858d98` / 蓝底 `#283e60`。标记不随界面语言或操作强调色改变；旁边仍显示完整 Provider 名称。这是用户明确选择的身份字母标记，不扩展为其他动作图标的字符替代规则。
- 并列字段宽度按 `1:1.1` 分配，间距 `14pt`；模型选择框填满当前列扣除 `8pt` 间距和 `128×32pt` 刷新按钮后的空间，不随所选模型名称缩窄。API Key 标题使用小号次要文字，“当前使用”使用绿色状态文字，“移除配置”使用透明底红色文字操作。
- API Key 区域始终显示安全输入框；字段标题与当前凭据状态同行，包括未配置、待验证、正在验证、已配置、验证失败、正在恢复和安全存储错误，字段内只放清空和显示/隐藏两个控件。新 Key 有非空改动时，字段外出现独立“验证”操作；未配置且输入为空时该操作禁用。键入或粘贴后的可验证状态即时更新，无须先移开焦点；清空后立即禁用，管理中心刷新不得使输入与按钮状态分离。恢复中及只读的安全存储读取错误不显示不可执行的验证操作；安全存储写入失败仍允许修改并手动重试，清空后保留禁用的验证操作。按 Return 与点击“验证”进入同一路径。
- API Key 是不透明文本：键盘输入的非换行字符按原样保留，不修剪空格、制表符或进行 Unicode 规范化。标准粘贴仅移除本次粘贴末尾至多一个 CRLF、LF 或 CR，再替换当前选区；显隐切换保持文本、焦点和选区，不触发提交。空值、仍含换行或超过 4096 UTF-8 字节的内容必须留在本地并显示具体输入提示，不能联网、写入或删除原凭据，也不能先截断再验证。
- 用户提交通过上述本地安全检查的新 API Key 时，应用先持久记录旧凭据作废，成功后才接受替换（ADR-0012）。若无法记录作废，拒绝本次替换、不发出验证请求、保留原凭据和配置，并显示本地安全存储错误。替换一旦被接受，旧 Key 立即失去回退资格；应用删除旧凭据与对应模型配置，再用新 Key 完成鉴权和完整分页模型列表获取。此后失败保持 Provider 未配置，保留本次输入供修正，不恢复旧 Key、旧模型或旧的全局当前选择。验证成功后先把新 Key 写入 Apple Keychain，再发布新缓存。
- 模型列表接口返回 401/403 时必须明确显示 API Key 被拒绝，不得误报为 Provider 临时不可用；传输、5xx 或模型列表协议失败仍按其真实类别终止，均不自动重试。
- 验证成功后保持同一张卡片展开，并在 API Key 旁展示当前模型选择框和刷新按钮。模型只能从列表选择，不支持手动输入。若新列表仍包含原先选择则保留它，否则清空并要求用户显式选择。
- 模型刷新采用原位忙碌态：API Key 的已配置状态、模型列表、当前选择及底部操作保持可见；仅刷新按钮在固定尺寸中显示进度和“刷新中”。冲突操作禁用但不移除，刷新期间不插入通用互斥提示，包括切换到其他 Provider 卡片时。普通网络或模型列表刷新失败保留凭据、缓存与选择，不误报为 Key 验证失败；失败提示替换模型说明，两者共用内容自适应高度的一行区域，不额外预留空白错误块。失败不自动重试、不弹成功提示。切换卡片或关闭后重开，仍展示原刷新任务的进度或终态；其他卡片可编辑草稿但不得提交。
- 首个完成配置的 Provider 仅在没有可用记忆选择时自动成为全局当前 Provider；随后配置的 Provider 不抢占当前选择。
- 已配置但不是全局当前的 Provider 显示“设为当前”；全局当前 Provider 显示“当前使用”。用户选择或更新非当前 Provider 的模型时不自动切换全局当前 Provider。
- 已配置 Provider 提供“移除配置”并要求确认。确认后删除其 Key、模型缓存与当前模型；若它是全局当前 Provider，则全局当前选择一并清空且不自动切换到其他 Provider。
- 凭据与配置一致时，打开 Provider 设置先显示缓存；缓存缺失或超过 24 小时才自动刷新。用户可手动刷新；应用不在启动、后台或每次截图前进行普通缓存刷新。启动或打开卡片发现 Keychain 中有凭据但缺少一致配置时，执行故障恢复并重新获取完整模型列表，不受普通缓存刷新时机限制；恢复成功前 Provider 不可用。
- 模型不可用错误会触发一次列表刷新。只有完整刷新成功才替换缓存；当前模型从列表消失时立即清除并要求重新选择，当前请求停止且不重复调用。
- 模型的图片能力状态为未知、已验证或不兼容。首次真实图片操作完成验证；只有可明确归类为不支持图片模态的错误才标记不兼容并清除当前模型，普通 HTTP 400 不足以改变状态。新 Key 或成功的新列表刷新把兼容状态重置为未知。
- 截图冻结、选区或模型请求活动期间 Provider 配置只读：API Key、验证、清空、模型选择、刷新、设为当前和移除配置均禁用；活动结束后恢复。Provider 凭据作业活动时，其他卡片可编辑窗口会话草稿但不能提交或变更配置。
- 验证提交必须原子捕获点击时的 Provider 和当前精确提交值。提交后字段、清空、显隐和验证操作保持只读直到该次验证终结，但用户仍可切换卡片或关闭管理中心。异步任务不得重新从视图、当前卡片或 Keychain 读取可能已经变化的值；迟到的验证结果只允许更新其原始 Provider，不得落到当前正在查看的另一张卡片。
- 尚未提交的 Key 草稿只属于当前管理中心窗口会话，切换卡片或关闭管理中心即清除。已经提交的验证属于应用级操作，关闭管理中心不会取消；提交时的 Key 只保留在内存中：成功安全存储后立即清除，失败后保留到用户修改、清空、移除配置或应用终止，不写入普通配置或日志。重新打开管理中心时，同一 Provider 重新连接到正在验证、待选择模型、已配置或验证失败的真实状态。
- API Key 按 ADR-0001 存入 Apple Keychain；稳定应用身份按 ADR-0005 使用 `com.loong.vlmsnapper`。
- API Key 验证成功但 Apple Keychain 写入失败时，Provider 不得被标记为已配置；应保留当前输入并显示本地安全存储错误，不得误报为 Provider 临时不可用。

### 8. 错误、限流与取消

- 所有 Provider 与本地错误映射为稳定的归一化类别。默认界面显示本地化原因和匹配的处理建议，不使用笼统“请求失败”。
- 至少区分网络、首次文字超时、流停滞、总超时、普通限流、额度/余额/套餐、鉴权、模型不存在或无权访问、图片模态不兼容、图片超限、内容安全、无效请求、响应不完整、输出截断和本地存储错误。
- 技术详情及复制内容只允许 Provider、模型、失败阶段、HTTP 状态、脱敏后的 Provider 错误码和 Request ID；不包含截图、原文、译文、API Key、认证头、原始请求或响应正文。
- 普通瞬时限流按 Provider 建立 1–5 分钟持久化冷却。有效 `Retry-After` 截断到该区间，无有效值时为 1 分钟；显示倒计时且不自动请求。其他 Provider 不受影响。
- 每日额度、余额、套餐或账户级配额错误不套用短冷却，直接建议检查账户或切换 Provider。
- 新操作中用户主动取消立即停止请求并保存“已取消”。应用启动时把遗留的准备请求、上传中或流式中操作终结为“意外中断”，丢弃残缺流但保留截图与请求元数据；两类状态分开显示，均只能由用户手动重新执行。既有记录重试的取消、中断不改写原终态，见 v1-core::REQ-002/AC-11。
- 正常退出或 Sparkle 安装前主动取消当前请求；新操作记录为“已取消”，既有记录重试按 v1-core::REQ-002/AC-11 处理。未走完正常关闭流程的遗留新操作才是“意外中断”。

### 9. 原始 PNG、历史与持久化顺序

- 模型操作使用并保存完全相同的原始 PNG 字节。文件保存于 `~/Pictures/VLMSnapper/YYYY-MM/`，命名为 `vlmsnapper-yyyyMMdd-HHmmss.png`；同秒冲突依次追加 `-2`、`-3`，绝不覆盖。
- 根目录和月份目录在首次模型操作保存时按需创建；“在 Finder 中显示”可创建根目录。v1 不提供自定义保存位置，也不跟随符号链接到其他位置。
- 内部数据库、结果、索引和日志位于沙盒 Application Support；分层存储遵循 ADR-0006，历史数据保护边界遵循 ADR-0002。
- 新操作首次执行时，先原子写入 PNG、计算 SHA-256，再创建“准备请求”历史记录。两步均成功且请求体预检通过后才允许网络上传。既有记录重试的身份与原图复用见 v1-core::REQ-002/AC-03，仍须满足原图所有权、请求体预检和数据库可用性门禁。
- PNG 保存失败时保留当前会话的内存截图并提供“重试保存”；关闭窗口或退出后丢弃，不创建历史。
- PNG 已保存但历史记录创建失败时，仅当文件是本次创建且 SHA-256 一致才回滚删除；无法回滚则作为孤儿文件保留，应用不自动认领或删除。
- Provider 已完成但最终数据库写入失败时，结果保留在内存并可复制；“重试保存”只重试数据库写入，不再次请求 Provider。关闭尚未保存结果前必须确认。
- 请求前按 Provider 的真实请求体计费方式检查图片大小。超限时不联网、不改图、不切换上传方式；新操作保留截图和失败记录，既有记录重试按 v1-core::REQ-002/AC-11 保留原记录；显示实际大小、限制与缩小选区建议。
- 只有当前安装创建、且历史保存的路径与 SHA-256 均匹配的文件是受管理截图。用户移动、删除或替换图片后保留文字与元数据，但禁止显示、上传、重新执行或删除不匹配文件。
- 数据库不可用时阻止新的模型操作，但允许设置、诊断和 Finder 操作，并提供重试、导出可恢复数据、显示数据库位置和重置。重置前保留故障数据库副本，不静默重建，遵循 ADR-0008。
- 数据库架构比应用更新时只读阻断写入，提示更新应用或在保留旧库后重置。

### 10. 历史浏览与清理

#### v1-core::US-001 在管理中心筛选历史

作为积累了多条截图操作记录的用户，我希望直接在历史页面按记录属性缩小结果范围，找到需要查看的原文或译文，而不是只能由底层查询接口筛选。

- v1-core::US-001/AC-01：管理中心历史页工具栏左侧提供“全部 / 提取 / 翻译”分段筛选，选择类型后列表只展示对应记录；不额外显示“操作类型”文字标签，保留辅助功能名称。中文简写仅用于历史列表和历史类型筛选；英文保留 All / Extract Text / Translate。
- v1-core::US-001/AC-02：历史页右侧搜索可匹配已保存原文或译文内容，结果列表不包含不匹配的记录。
- v1-core::US-001/AC-05：Provider 下拉框直接位于历史工具栏的类型筛选和搜索之间；选项为全部 Provider 及本地历史记录中出现的 Provider，不依赖当前配置或联网模型目录。选择后只显示对应记录；没有高级筛选展开入口。
- v1-core::US-001/AC-09：用户可在管理中心筛选钉住记录；钉住状态不等于把结果窗口置顶。

- v1-core::US-001/AC-10：类型、Provider、文字搜索即时生效并按 AND 组合；清空搜索仅移除文字条件。History 与 Pinned 间切换保留查询，Pinned 仅追加钉住交集，返回 History 仅移除钉住限制。
- v1-core::US-001/AC-11：同一管理中心窗口会话内往返设置保留查询；真正关闭再打开管理中心重置为全部类型、全部 Provider 和空搜索。截图退让等暂时隐藏不视为关闭。
- v1-core::US-001/AC-12：查询或历史数据变化后，原选中记录仍匹配时保留选中；否则选择第一条匹配记录，结果为空时清空详情。详情图片不得残留为另一条记录的图片。
- v1-core::US-001/AC-13：历史记录列表宽 260pt（包含右侧 1pt 分隔线），右侧详情填满剩余空间，全部管理中心页面共用 180pt 宽应用导航。无常驻滚动条占位时行盒宽 249pt；行盒左右和首尾各留 5pt，行间距 5pt，圆角 9pt，内容内边距 10pt。标题 13pt bold、摘要 11pt regular、元信息 10pt regular；标题后距 6pt、摘要后距 7pt。标题和摘要均单行省略；摘要优先译文、其次原文、最后状态文字，不显示行内 Pin 图标。
- v1-core::US-001/AC-14：类型按钮使用紧凑的灰底分段组和浅色选中块，三个按钮并排；不采用浮起 Capture 按钮样式。中文按钮最小宽度 54pt、水平内边距 9pt，英文按文字宽度扩展而不截断。
- v1-core::US-001/AC-15：记录行类型文字统一蓝色；完成绿色、取消橙色、失败和意外中断红色，均保留明确文字。浅色类型/完成/取消/失败色为 #1553B2 / #20835B / #A96609 / #C34242，深色为 #9BC0FF / #62C596 / #EFB45F / #FF8080。类型与状态间距 7pt，标签与时间至少间隔 10pt；时间右对齐，空间不足可换到下一行仍右对齐，行间隔 5pt；不改变区域日期格式。
- v1-core::US-001/AC-16：历史列表选中条目仅背景高亮，不加边框或内描边，悬浮选中项不改变选中表现；保留独立键盘焦点提示。浅色普通/悬浮/选中背景为 #FFFFFF / #E8ECF1 / #DCE6F5，深色为 #2B2F36 / #343A43 / #314361，不随系统强调色改变。标题/摘要/日期浅色为 #202329 / #646B75 / #8A929D，深色为 #F2F3F5 / #B4BAC3 / #858D98。最左侧应用导航同样不加选中边框。
- v1-core::US-001/AC-17：管理中心首次显示以普通窗口铺满当前屏幕可用区域，保留菜单栏和窗口按钮，不进入 macOS 独立全屏空间；用户调整后的窗口尺寸与位置在更新、页面切换和临时隐藏后保留。
- v1-core::US-001/AC-18：应用导航分为资料库与设置中心，显示历史总数、钉住总数和支持的 Provider 数量；不显示当前 Provider 摘要卡片。
- v1-core::US-001/AC-19：菜单栏面板底部左侧 Provider 进入 Provider 配置页，右侧 Settings 进入通用设置页；跳转后只有目标导航项选中，不残留历史选中态。

#### v1-core::REQ-002 筛选结果的历史操作

适用范围：管理中心历史列表，包括筛选后的列表；记录身份及成功提交、失败保护规则同时适用于历史详情内联重试和仍打开的当前结果重跑。重试指对同一记录的同一操作类型再次执行，不包括新截图或从未执行过的另一操作类型。

历史详情重试恢复原记录身份；同一记录替换、失败保护与持久化恢复遵循下列验收条件。

- v1-core::REQ-002/AC-01：单击一条记录只更新当前详情。
- v1-core::REQ-002/AC-02：双击记录不附加额外动作，仅保持该记录在右侧详情展示；不打开独立结果窗口、不自动请求 Provider、不创建历史记录。
- v1-core::REQ-002/AC-03：已有持久化记录且原始截图仍可用时，用户从历史详情或仍打开的当前结果发起重试，始终绑定原记录身份；不新增历史行、不复制原图文件，不因重建工作区或连续重试而失去绑定。不允许先新增再删除或按图片内容合并不同记录。
- v1-core::REQ-002/AC-04：原始截图已移动、删除或替换时，仍可查看、搜索、复制已保存文字与元数据，但不显示或上传不匹配图片，不允许依赖原图重跑。
- v1-core::REQ-002/AC-06：新截图来源的结果关闭和应用退出不自动打开管理中心。
- v1-core::REQ-002/AC-07：历史详情标题栏右上角依次保留重试、Pin、删除图标按钮；重试使用顺时针箭头，悬停提示“重试 / Retry”，固定尺寸中原位展示进行中状态。初次选中记录也加载原图；未就绪、原图不可用、活动冲突或待保存结果时保留禁用按钮。
- v1-core::REQ-002/AC-08：点击历史详情重试使用提交时当前可用 Provider/模型、原记录的操作类型和目标语言，重新校验原图后显式发送一个请求；记录身份遵循 v1-core::REQ-002/AC-03。
- v1-core::REQ-002/AC-09：历史详情重试的任务及未保存结果连同目标记录身份由应用持有，管理中心临时隐藏或关闭不丢失；重开可继续查看同一记录对应的进度或待保存结果。应用退出前确认丢弃未保存结果，取消退出则继续保留。
- v1-core::REQ-002/AC-10：仅在 Provider 返回完整成功结果且本地提交成功后，原子替换原记录的原文、译文、完成状态、实际 Provider/模型、耗时与 usage；不混入上次文字或指标。记录 ID、原图引用及 SHA-256、原始创建时间、操作类型和目标语言保持不变；重试提交不修改 Pin，包括不回滚用户在请求期间对 Pin 的修改；其他记录不变。

- v1-core::REQ-002/AC-11：本地预检失败、请求失败、超时、响应截断、主动取消或提交前应用中断均保留原记录的已持久化内容、元数据及终态；本次进度、流式文字和失败提示不覆盖原持久化结果，不新增失败或取消副本。此保护同样适用于原本失败、已取消或意外中断的记录。重启后不自动恢复请求、不将原终态改为本次的中断状态。
- v1-core::REQ-002/AC-12：Provider 成功而本地保存失败时，保留完整内存结果及原目标记录身份，原数据库内容不变；允许复制及显式“重试保存”，只重试该记录的本地原子更新，不再次请求 Provider。未保存结果的关闭确认沿用既有生命周期规则。
- v1-core::REQ-002/AC-13：目标记录在请求前已不存在时，不发送请求；目标在提交时已不存在时，不报告保存成功。两者均通过既有错误反馈说明目标失效，不降级为新增或更新其他记录。
- v1-core::REQ-002/AC-14：重复点击重试不产生并发或重复请求；存在 Provider 配置作业、其他活动模型任务或待保存结果时，不开始冲突重试，不新增或修改历史。
- v1-core::REQ-002/AC-15：历史详情重试的进度、成功或失败显示在当前右侧，不打开独立结果窗口；所有阶段均不在正文添加“重试”过程标题及重复的 Provider/模型，成功后不额外显示“完成”提示。右上角重试按钮原位显示活动状态，进行中、失败、取消及待保存反馈保留。切换选中记录后迟到响应仍只归属发起记录，不能覆盖其他记录的详情。失败后原已保存文字仍可读。
- v1-core::REQ-002/AC-16：请求中或结果未保存时暂停历史删除和清理，删除及清空历史入口禁用，迟到的删除确认也不得删除重试目标；请求终结且无待保存结果后恢复。
- v1-core::REQ-002/AC-17：成功提交后，列表摘要、详情、搜索及筛选从同一条已更新的持久化记录取值；切换记录、关闭重开及重启应用后均可按原 ID 读回新结果，不依赖本次重试的内存覆盖。查询匹配变化后的选中协调遵循 v1-core::US-001/AC-12。
- v1-core::REQ-002/AC-18：详情图片背景铺满右侧内容可用宽度，带浅色细边框和圆角；图片保持比例居中、限高 100pt，图片与背景间上下内外边距均为零。图片与文字以浅色分隔线分区；翻译的原文与译文布局遵循 v1-core::US-002，提取记录不创建空译文区，重试前后使用同一层级。
- v1-core::REQ-002/AC-19：点击可用图片在管理中心内打开原图放大预览，默认适应窗口，可切换 100% 原尺寸并滚动查看；关闭按钮或 Esc 返回原详情、保留选中记录。预览只使用已校验的原图，不打开外部文件路径、不发网络请求或更改历史。缺图或图片不属于当前记录时不可打开；关闭管理中心同时结束预览。
- v1-core::REQ-002/AC-20：原图预览内滚轮直接连续缩放，无需修饰键，鼠标所在图像点保持在原位置（触及边界时允许居中/限位）；滚轮不同时平移或滚动背后的历史页。放大后按住左键拖拽平移，并保留滚动条。默认适应窗口，保留“100% 原尺寸 / 适应窗口”切换，手动缩放后按钮可恢复适应窗口。缩放下限为 5% 与适应比例的较小值，上限 800%；零滚动不改变模式，超限停止而非翻转；只影响当前预览，关闭重开恢复适应窗口。触控板滚动沿同一路径缩放，不把惯性尾段继续当缩放输入。

- v1-core::REQ-002/AC-21：首次进入或切换历史记录时，原图读取期间仅保留空白图片区，不显示加载文字或转圈，也不提前显示失败；只有本次读取、所有权/哈希校验或图像解码明确失败后才显示既有不可用提示，已保存文字仍可读。
- v1-core::REQ-002/AC-22：同一记录重新读取、刷新或重试时保留已经校验的图片，不先闪空；若重新读取明确失败才移除图片并显示不可用提示。失败后重新选择可再次读取，恢复成功后清除提示。
- v1-core::REQ-002/AC-23：切换记录立即停止展示上一条的图片；迟到读取结果不得覆盖当前选择，即使按 A→B→A 切回同一记录，也只接受最新一次读取结果。删除选中记录或应用停止后，旧读取不得恢复图片。

#### v1-core::QR-001 管理中心最小尺寸可用性（直接验收）

适用范围：历史与设置共用管理中心；最小内容区为 `920×620pt`，缩到最小时标题栏、列表底栏和详情内容均不被窗口外框裁切。

#### v1-core::CON-001 历史检索的本地处理边界（直接验收）

适用范围：搜索、筛选和查看已保存历史；全部在本地执行，不向模型或其他服务发送历史内容。只有用户显式触发模型操作，才允许按模型操作的既有门禁发送对应原始 PNG（ADR-0002、ADR-0006）。

#### 历史详情与清理
- 管理中心侧栏使用确认的浅层导航表面；历史详情在带描边的独立卡片中显示原始截图可用性、结果、Provider、模型、首字耗时、总耗时和 Provider 实际返回的 token usage；不估算费用。
- 默认保留期为 30 天，可选 7、30、60、90 或 180 天，不提供自定义值或永久保留选项。钉住记录不参与自动清理。
- 自动清理在启动后执行一次，此后最多每 24 小时一次。缩短保留期前显示将删除数量并确认，确认后立即清理；延长不触发清理。活动记录跳过。
- 删除是永久操作，不进入废纸篓且不可撤销。手动删除钉住记录必须确认；清空历史允许选择是否包含钉住项。批量删除遇到单项失败继续处理其他项，最后报告成功与失败数量。
- VLMSnapper 不同步历史。Time Machine、云盘或其他工具生成的外部副本不受应用清理保证。

### 11. 本地化、隐私与诊断

#### v1-core::REQ-003 界面语言与区域格式

适用范围：全部原生界面，包括新增历史筛选；遵循 ADR-0003。

- v1-core::REQ-003/AC-01：v1 UI 支持简体中文和英语，默认跟随系统，允许手动切换；切换后要求重启。
- v1-core::REQ-003/AC-02：日期与数字遵循用户区域设置，不随 UI 语言覆盖改变。

#### 隐私与诊断
- v1 不制作 RTL UI 镜像，但结果内容必须正确显示双向文本。
- 不采集遥测。诊断日志只记录允许的时间、Provider、模型、阶段、耗时、HTTP 状态、脱敏错误码、脱敏 Request ID 和归一化错误类型，保留 7 天并支持用户导出。
- 面向用户的隐私说明表达为数据保存在这台 Mac、受 macOS 用户权限保护、API Key 在 Apple Keychain；不得把内部加密实现措辞直接展示给用户。

### 12. 更新与分发

- v1 仅通过 Developer ID 直接分发，不发布 Mac App Store，遵循 ADR-0007。
- 使用 Sparkle 稳定通道。自动检查默认开启，固定每 6 小时且只提供开关；不自动下载更新，也不提供自动下载开关。
- 发现新版本后在菜单栏和通用设置中提示，由用户显式开始下载。菜单栏与设置页监听同一应用级 Sparkle 状态，只有 Sparkle 确认下载完成后才显示“已下载”。下载完成不打断截图或模型任务，在退出时安装，也允许用户选择立即重启并更新；应用连续运行 7 天仍未安装时温和提醒一次。手动检查更新只在通用设置中提供。
- appcast 使用 HTTPS；应用和 DMG 通过 Developer ID 签名、Apple 公证与 stapling，更新包另有 Sparkle EdDSA 签名。
- Universal、Apple Silicon、Intel 分别打包并订阅独立 appcast，保持当前安装架构，遵循 ADR-0004。三个产物必须使用相同版本和 Sparkle 公钥；任一架构的签名、公证、stapling 或更新签名失败，整个版本不发布。
- 三个 Developer ID 应用必须嵌入同一份与 `com.loong.vlmsnapper` 匹配的分发 provisioning profile。正式签名从 profile 动态派生 App ID Prefix、Team ID、完整 application identifier 和精确 Keychain access group，不在仓库中硬编码账号前缀。
- provisioning profile 是仓库外的发布输入，不进入 Git。缺失、无法验签或解码、过期、分发渠道错误，或与 Bundle ID、Team ID、Developer ID Application 证书、Keychain allowlist 不一致时，正式流水线必须在签名前失败，不得回退到无 profile 或 legacy Keychain 构建。
- 最终已签名 App 必须声明 profile 授权的精确 application identifier、Team ID 和 Keychain access group。三个架构均做 profile/签名静态一致性验证；Universal 产物还必须由最终已签名的应用进程执行一次 Data Protection Keychain 的增、读、改、删验收。

## Failure Modes

以下按用户实际操作序列定义终态；更细的归一化错误类别仍遵循上文。

双语对照新增边界按 v1-core::US-002/AC-03、AC-04、AC-06–10 核对：流式中拖选、重复文本、Unicode 转义跨块、跨句选区、空图片、结构截断、失败/取消后回看旧结果、保存失败再本地保存、旧库迁移和切换记录。不得把按标点重新切分旧历史当作映射迁移。

1. 用户通过快捷键或主面板按钮触发截图，但没有可用 Provider/模型：不请求屏幕权限、不冻结屏幕；把首次引导窗口带到最前并提供前往设置中心 Provider 页面的入口。
2. 用户通过快捷键或主面板按钮触发截图，但权限未授予或已撤销：不捕获，显示原因和系统设置入口；授权后要求重启；把首次引导窗口带到最前并展示权限恢复入口。
3. 部分显示器冻结失败：失败屏不可选，其他屏继续；全部失败则退出且无历史。冻结失败、当前进程无法从同一内容快照解析，或新遮罩无法覆盖任何显示器时，保留此前已打开的结果工作区或选区，不留下半退让状态。
4. 用户拖出过小或跨越失效显示器的选区：保持选择模式，不生成 PNG。
5. 用户在模型操作前取消：释放内存截图，无文件、无历史、无网络。
6. 用户点击操作，但 PNG 无法保存：无网络，内存保留并允许重试保存；关闭后丢弃。
7. PNG 成功而准备记录失败：无网络；仅删除所有权和哈希均可证明的本次文件，否则保留孤儿。
8. 请求体预检超限：不联网、不改图；新操作保存失败记录，既有记录重试遵循 v1-core::REQ-002/AC-11；建议缩小选区。
9. Provider 调用出现网络、超时、限流、鉴权、安全或协议错误：立即停止，不自动重试；新操作丢弃残缺流并保存归一化失败。既有记录重试按 v1-core::REQ-002/AC-11 保留原记录。
10. Provider 明确模型不支持图片：失败并清除当前模型，标记不兼容；普通 400 不触发该变化。
11. 模型不存在：只刷新列表一次；确认消失则清除并终止，刷新失败保留旧缓存但本次仍失败。
12. 用户在请求中关闭结果窗口或主动取消：停止请求；新操作保存已取消，不保留残缺文字。既有记录重试遵循 v1-core::REQ-002/AC-11；历史详情的管理中心关闭遵循 v1-core::REQ-002/AC-09，不等同于关闭活动结果窗口。
13. 应用崩溃或断电后重启：遗留新操作的非终态变为意外中断，不自动恢复请求。既有记录重试的提交前保护见 v1-core::REQ-002/AC-11，已提交结果的恢复见 v1-core::REQ-002/AC-17。
14. Provider 完成但最终结果落库失败：结果只驻留内存且可复制，只允许重试数据库保存；关闭前确认。
15. 用户移动、删除或替换受管理 PNG：保留文本和元数据，不显示、不上传、不删除不匹配文件。
16. 自动清理或批量删除部分失败：继续其余记录并汇总结果；不把失败项误报为已删除。
17. 历史数据库损坏或版本过新：阻止新模型操作和写入，不静默新建；保留恢复路径。
18. 更新准备安装时存在活动请求：先正常取消；新操作持久化取消状态，既有记录重试遵循 v1-core::REQ-002/AC-11，再退出安装。尚未保存结果继续遵循退出确认规则。
19. 应用附着面板打开时退出：仍进入统一退出协调；若未保存结果确认被取消，应用继续运行且原面板保持打开。
20. 用户验证有效 API Key，但当前已签名应用没有 Data Protection Keychain 授权或本地 Keychain 写入失败：验证流程终止，不保存 Provider 配置，显示本地安全存储错误及可操作建议，不改写为网络或 Provider 错误。
21. 发布者启动正式构建，但 provisioning profile 缺失、过期、损坏，或与应用身份、签名证书、Keychain allowlist 不匹配：在任何可发布产物签名或上传前终止，不留下可被误当成正式发布的降级产物。
22. provisioning profile 验证通过，但 profile 授权与最终 App 签名实际声明不一致，或 Universal 产物的 Data Protection Keychain CRUD 失败：整个三架构版本失败，不进入公证、分发或 appcast 发布。
23. 用户在结果工作区已进入成功、失败或取消终态且结果已安全保存后触发截图：先冻结排除 VLMSnapper 自身的当前屏幕；只有新选区遮罩成功覆盖可用显示器后，才退下结果窗口并提交工作区替换。任何前置步骤失败都恢复旧工作区继续可用，旧结果同时保留在历史记录中。
24. 用户在结果工作区仍有活动请求或未保存结果时触发截图：不替换工作区、不冻结屏幕，把当前结果窗口带到前台；同一工作区的退让请求只消费一次，不能与 Try Again 并发启动。
25. 用户在菜单栏面板、管理中心或已有选区中触发截图且当前允许开始新截图：这些来源界面在冻结期间保持可用，但由 ScreenCaptureKit 排除在冻结帧外；新遮罩成功显示后才退下明确记录的来源界面。重复截图必须先显示新遮罩再释放旧遮罩和冻结帧，不能出现桌面闪烁或失败后丢失旧选区。
26. 历史记录单击、双击、显式重跑及原图不可用的独立条件见 v1-core::REQ-002。
    读取未完成、同记录刷新与快速切换的显示规则见 v1-core::REQ-002/AC-21–23；不得把尚未取得图像等同于文件失效。
    图片预览仅绑定打开时的已校验图像，不跟随迟到的其他记录加载；宽图和长图均保持比例，原图可滚轮缩放及拖拽平移，缩放限位、惯性忽略与重开复位只作用于当前预览。缺图无放大入口，关闭预览不关闭历史列表。布局与预览见 v1-core::REQ-002/AC-18–20。
    重试按钮及请求选择见 v1-core::REQ-002/AC-07–08，窗口生命周期见 v1-core::REQ-002/AC-09，成功提交、失败、保存失败、目标消失、重复点击、切换记录及删除清理见 v1-core::REQ-002/AC-10–17。原图失效见 v1-core::REQ-002/AC-04；普通窗口铺满屏幕见 v1-core::US-001/AC-17。
27. 用户从首次引导进入 Provider 设置后只验证 Key、尚未选择模型：停留在当前 Provider 卡片，不返回引导；选择有效模型后自动返回引导并显示完成状态。用户提前关闭设置中心时，直接返回引导并保留实际配置进度。
28. 用户在已配置 Provider 输入新 Key 并点击验证：先持久记录旧凭据作废，再接受替换并移除旧 Key、旧模型缓存及该 Provider 的当前模型；验证、模型列表获取或后续安全存储失败不恢复旧配置。若作废记录无法持久化，则拒绝本次替换、不发请求、保留原配置并提示安全存储错误；存储恢复后重开可读取原配置。作废已经持久化但旧条目删除失败时，重开只允许清除明确已作废的旧条目，不能把它当作遗留凭据恢复。
29. 用户验证新 Key 后，Provider 返回的完整模型列表仍含旧模型：保留旧模型选择；列表不含旧模型：进入待选择模型。两种情况都不因该 Provider 可用而抢占另一个全局当前 Provider。
30. 用户移除非当前 Provider：只清除该 Provider；用户移除全局当前 Provider：同时清空全局当前选择，不自动切换到其他可用 Provider，下一次截图按缺少当前 Provider 的流程进入引导。
31. 用户在截图冻结、选区或模型请求进行中进入 Provider 页面：所有卡片仍可查看，但 API Key、验证、清空、模型选择、刷新、设为当前和移除配置全部只读；活动结束后恢复。

32. 用户打开 Provider 卡片但 Keychain 载入尚未完成：字段不接受键盘、粘贴、清空、显隐或验证操作；载入完成后一次性呈现该 Provider 的真实字段与状态。用户在此期间切换卡片时，迟到的载入结果被忽略，不改变新卡片。
33. Provider 配置当前可编辑时，用户通过键盘或 `Command-V` 输入非空有效 Key：占位文案立即消失，清空和验证立即可用，字段与状态同时进入“待验证”；任一项仍显示空值状态都视为失败。移除已有配置必须走“移除配置”，不能把空输入当作新凭据。
34. 用户在 Key 编辑过程中清空字段：字段回到空态，清空与验证禁用；尚未点击验证时不删除 Keychain 中的旧凭据，关闭并重新打开管理中心后恢复已保存配置。
35. 用户切换到另一张 Provider 卡片：未提交草稿被丢弃，新卡片只加载自己的凭据状态；不额外确认。之前 Provider 的迟到 Keychain 结果不得改变新卡片的文本、状态或按钮可用性；已经提交的验证继续执行并仍只更新其原始 Provider。
36. 用户点击验证或按 Return 后立即切换卡片：本次请求使用提交瞬间捕获的 Provider 与精确 Key；原卡片字段在验证终结前只读，结果只归属该 Provider。用户返回原卡片时看到正在验证或已经到达的终态，不会产生第二次验证。
37. 用户在安全输入与明文显示之间切换：文本、插入点、选区和焦点保持；切换本身不改变“待验证”判断，不触发验证或写入安全存储。
38. 管理中心因应用状态更新而重新呈现 Provider 页面：当前窗口会话中的字段文本、状态、占位文案以及清空/验证可用性仍来自同一编辑状态，不能出现文本已显示但操作仍按空值禁用的分裂状态。
39. 已配置 Provider 的字段精确值与已载入凭据完全相同时：不显示待验证操作，按 Return 不发起验证，也不删除现有凭据；只有精确值实际发生非空变化后才能提交替换。
40. 用户在 Keychain 载入或尚未提交的编辑状态关闭管理中心：取消载入并清除窗口会话草稿，已保存凭据不变。用户在正在验证时关闭：验证继续执行；重新打开后显示同一验证或其终态。失败时保留提交 Key 供修正，成功时只在安全存储写入成功后清除内存候选。
41. 应用在验证进行中正常退出、崩溃或被强制终止：取消仍可取消的请求并丢弃只存在内存中的候选 Key；已经接受替换并持久记录作废的旧配置不恢复。下次启动时不重新提交已经丢失的候选 Key；若新 Key 已经写入 Keychain，则按安全存储真相进入模型配置恢复，否则显示未配置。若退出前尚未接受替换，则保留原配置；迟到的凭据读取返回后不得再发验证请求。
42. 用户键盘输入 Key：空格、制表符和其他非换行字符按原样保留。用户粘贴 Key：只移除该次粘贴内容末尾至多一个 `CRLF`、`LF` 或 `CR`，再插入当前选区；其他字符不修剪、不规范化。结果为空、仍含换行或超过应用明确的 4096 UTF-8 字节安全上限时，保持编辑状态并显示本地输入错误，不删除旧配置、不联网，也不截断内容后尝试验证。
43. 一个 Provider 正在验证时，用户切换到另一张卡片并输入新 Key：草稿正常保留在当前窗口会话，但验证操作保持禁用并显示现有只读提示条；前一项进入任一终态后，若草稿仍合法且非空，验证操作自动恢复。重复点击或按 Return 不产生第二个验证请求。模型刷新同样禁止冲突提交，但不插入提示条或隐藏已有控件；切卡片后返回仍保留刷新前的列表和选择直到请求完成。普通刷新失败保留配置并原位展示可重试错误，成功但所选模型消失时清空选择。
44. Provider 凭据作业已经开始后，用户触发截图快捷键或菜单栏截图入口：不冻结屏幕、不创建选区，把管理中心的 Provider 页面及当前作业带到前台；截图操作栏不会出现“配置处理中”状态。已有结果工作区的 Try Again 同样禁用，不启动模型请求、不新增或修改历史记录。反向地，截图冻结、选区或模型请求已经活动时，Provider 验证提交被拒绝，凭据恢复按 FM-46 等待原活动终结后再开始，原有截图或请求不受影响；双方进入终态后恢复相应入口。
45. 用户打开 Provider 卡片读取凭据：Keychain 返回条目不存在时显示未配置；返回权限、entitlement、访问控制或其他读取错误时显示本地安全存储错误并保持字段只读，不得伪装成未配置。用户收起再展开时发起新的读取，旧读取结果不能覆盖新代次。
46. 新 Key 已成功写入 Keychain，但应用在发布模型缓存或 Provider 状态之前失败、崩溃或终止：下次启动或打开卡片时发现“有 Key、无一致配置”，自动进入恢复并重新获取完整模型列表；恢复作业开始后阻止新的截图、Provider 验证和模型请求，若截图冻结、选区或模型请求已经活动则等待其终结再开始。恢复成功前 Provider 不可用。反向发现“有配置、无 Key”时清除残留配置和全局当前指向。

## Implementation Decisions

- 双语展示由两个独立语言栏承担各自标题、正文排版和复制，共享协调器只同步片段身份及选择/悬停状态。候选尺寸测量与正在显示的文本排版分离，探测尺寸不能改变显示中的换行或选区；外层只分配等宽栏和较高正文所需高度。
- 使用原生 Swift/SwiftUI 与必要的 AppKit 桥接实现 macOS 14.4+ 菜单栏应用；以 ScreenCaptureKit 的当前进程内容快照及同快照全局回退捕获冻结帧，以系统安全存储保存密钥，以 Sparkle 负责直接分发更新。
- 以应用工作流状态机作为主协调边界：屏幕冻结、选区、内存截图、PNG 持久化、准备记录、Provider 请求、流式解析和最终持久化必须具有显式状态及唯一终态。
- Provider 抽象只暴露模型列表获取、图片请求事件流、取消和归一化错误，不把各厂商响应结构泄漏给结果 UI 或历史层。
- 翻译使用单个结构化 JSON 片段集合，每个片段携带本结果内唯一身份、块身份、标题/段落/列表类别以及原文和译文；相同块中的片段连续排版。增量解析能在完整对象结束前公布安全的文字前缀，最终须校验结构。文本与对应关系同事务存储；旧数据保持无映射。原生文本视图用 UTF-16 文本范围连接片段身份，不把模型内容作为网页执行。
- 原始 PNG 与历史记录采用分层所有权模型；删除权限由当前安装创建标记、保存路径和 SHA-256 三者共同决定。
- 新操作创建与既有记录重试使用显式区分的执行上下文；历史恢复上下文携带持久化记录身份及原图、操作类型和目标语言，不从当前选中项、图片内容或前次执行的内存缓存推断。一次尝试的状态与已提交的历史快照分离；提交目标缺失不能转为创建。该边界承兑 v1-core::REQ-002/AC-03、v1-core::REQ-002/AC-10–13，不改变现有历史架构及截图所有权决策。
- 全局活动任务、Provider 冷却、当前 Provider/模型和单实例身份均为应用级状态，不能由单个窗口生命周期拥有。
- 截图、模型请求和 Provider 凭据作业共用持有者令牌互斥边界；只有持有者可以释放，选区到模型请求原子转换，迟到释放不能结束后继作业。恢复等待通过活动结束通知唤醒并响应取消，不轮询、不通过固定延迟抢占。
- Provider 设置的页面状态与配置状态分离：折叠卡片、Key 显隐和未提交草稿属于当前管理中心会话。可观察的凭据编辑状态统一持有显示值、精确字节基线和载入身份；每次打开或切卡片产生唯一载入身份，关闭后迟到结果不再有发布资格。提交时同步捕获不可变 Provider/Key，已提交作业及失败候选由应用生命周期持有，不随窗口关闭而取消。Keychain 凭据、模型列表、每 Provider 当前模型和全局当前 Provider 仍由应用级协调器拥有。首次引导只传递一次性的返回来源，不复制 Provider 状态。
- 所有用户可见字符串进入本地化资源；代码、注释和模型提示词使用英语。
- 相关架构决策：ADR-0001 至 ADR-0012。其中 ADR-0006 修订 ADR-0002 早期的截图路径描述，当前实现以 ADR-0006 为准。

## Testing Decisions

双栏布局回归须读取实际显示文本的字形宽高及完整字形范围，覆盖长旧记录、长 URL、长短不对称、窄宽往返和流式追加保留对应选区。额外探测未提交的候选尺寸后，显示中的换行必须不变；不能仅靠裁剪边界或短文本截图证明无覆盖。原生渲染和程序化选择不替代安装版物理操作或卡顿故障中采样。
### Seam 1：应用工作流契约

以不依赖真实窗口和真实网络的应用协调器公开行为为最高层 seam，验证从快捷键/选区/操作到成功、失败、取消、意外中断的状态转换，以及“先持久化、后上传”“单次点击单次请求”“旧成功结果只在新成功后覆盖”等不变量。Provider 配置通过同一公开协调边界验证直接替换、无回退、模型保留规则、移除当前 Provider 不自动回退、非当前 Provider 不抢占选择和活动请求只读。该 seam 覆盖绝大多数用户操作序列和竞态。

凭据编辑通过公开的编辑会话接口验证精确基线、载入身份、提交身份与关闭/重开。会话验证测试使用真实配置协调器，只在外部模型请求和持久化边界控制延迟与失败；原生输入测试通过真实 AppKit 窗口验证占位、选区、显隐、菜单 Paste、Return 与按钮。独立进程菜单验收必须重建源码、限时退出并产生明确完成标记；它不替代安装版真人键鼠、真实 Keychain 或联网验收。

标准无障碍输入同样连接到真实凭据编辑状态：密码和明文模式写入后即时更新可验证状态，清空、不可编辑状态及精确字节语义不变。外部无障碍测试使用已授权客户端与隔离假凭据，通过生产界面的输入、按钮状态、按钮动作直到精确提交结果，不以动作成功代替业务结果；不在测试工具中伪造文本变更通知。该路径不证明物理鼠标命中、键盘焦点或真实服务端鉴权。

Provider 按钮交互的自动回归通过独立测试 target 承载生产界面，每次从当前源码构建，由固定授权 AX 客户端按唯一语义属性定位；不依赖窗口内硬编码点击坐标或持久引用临时 PoC 产物。空值/预填、显隐、清空重填、快照刷新、不同窗口尺寸及作业锁定/解除覆盖同一提交结果；非法输入通过同一按钮的启用→禁用→启用交叉检查。保留 AppKit 编辑、菜单粘贴与 Return 的独立测试。负对照必须已到达公开提交回调，再因缺少最终业务效果而失败；授权或环境失败不算预期红。完整本地门禁为 `Scripts/test-local-regression.sh`，托管 CI 的报告验证不等于外部 AX 桌面验收。

快捷键、菜单截图和结果重跑共用生产使用的 ApplicationWorkflow 准入入口，窗口与冻结副作用在准入之后注入；禁止用仅测试使用的路由器替代生产接线。重跑测试使用真实工作区、持久化 runner 和临时 SQLite，经历史公开接口读取结果。该测试不替代签名安装版的物理快捷键、屏幕冻结或窗口前台验收。

既有记录重试以生产历史详情回调为最高层集成测试边界，复用真实应用装配、工作区、持久化执行器和临时 SQLite，仅控制外部 HTTP 及存储故障；仍打开的当前结果重跑另守会话边界。不能只测同一执行器的第二次调用：须从已落库记录和全新执行上下文进入，覆盖提取与翻译、重复及连续重试、成功/失败/取消/截断、保存失败后本地重试、缺图/目标消失、切换详情和删除清理保护。成功后的判据是经公开持久化查询核对同一 ID、条数、内容及保留元数据，并重建应用只保留磁盘数据后再次读回；不能只断言当前详情或内存列表。另用无关记录及新截图首次操作验证保护与创建边界。对应 v1-core::REQ-002/AC-03、v1-core::REQ-002/AC-04、v1-core::REQ-002/AC-08–17；应用重建测试不声称等同真实断电验收，程序化回调不声称等同安装版物理点击。

#### 应用组合验收的依赖注入方案（已确认，分步实施）

> Verification boundary: 同一生产 delegate 的引导入口、原生输入/Return、验证、模型菜单选择、关闭重开、返回引导及重建恢复已有组合测试；验证与冻结的双向阻断、合成冻结帧经选区与操作栏到模型流解码和历史保存、被阻止重跑时历史不变、成功重跑更新原历史、模型请求结束后唤醒凭据恢复均有应用组合覆盖。实际主菜单 Paste 使用真实 key window 和隔离剪贴板；持续关闭期间完成验证、普通抛错与取消后的测试夹具释放另有原生 XCTest 覆盖。测试使用假凭据、隔离存储和受控外部响应，不等于真实账户或物理键鼠验收。用户已确认本轮安装版交互与视觉修改通过，不再把这些已反馈的操作笼统列为 Pending；Provider 卡片标记选型已确认采用 DS / OA / G；完整同状态原型对照仍归收口票。历史 key-window/操作栏等待超时的根因仍未确认，单列本地 Ticket 24 跟进，不与已经复现并调整测试生命周期的 teardown 崩溃混为一谈。连续完整测试通过只能作为回归样本，不能证明该超时已消失。

v1-core::REQ-001 的应用组合测试通过隔离通知中心驱动真实会话与原生遮罩，但不能替代签名 App 中实际拔插、修改显示设置和多屏继续选择的验收。

历史筛选复用现有管理中心原生控件、应用组合与真实临时 SQLite 边界，不为补验收另建模拟历史页面。v1-core::US-001 的类型、Provider、搜索及钉住交集通过实际控件 → 生产绑定 → 列表/详情验证，同时准备匹配与不匹配记录；数据库查询测试只作为补充，不能替代入口可用性。会话保留、选择协调与零匹配覆盖窗口关闭及临时隐藏两个路径。v1-core::REQ-002、v1-core::QR-001、v1-core::CON-001 与 v1-core::REQ-003 是同一路径的回归条件。

现有 `VLMSnapperApp` executable target 可被测试直接引用；保留 target、源码位置和 `main.swift`，不为测试新拆共享模块。Model 与 delegate 启动边界均使用显式外部依赖构造注入；主实例仍使用真实锁，取得资格后才构造 Model 依赖。程序化原生测试走生产窗口和控件绑定，不用 Model 回调测试抵扣窗口路由。测试涉及进程级主菜单、本地化及窗口状态，组合 suite 与其余 suite 分进程运行，两个进程均须通过，不能省略其中一组。

正式入口和组合测试应使用同一份应用装配、窗口路由与业务实现。只在外部网络、系统凭据、屏幕权限/冻结及启动所触及的系统能力处传入 adapter；编辑会话、Provider 配置协调器、工作流互斥、持久化 runner、真实临时数据库和窗口控制器不能替换成模拟实现。尽量复用现有 interface，网络在 HTTP 层控制，保留模型列表解析与图片流式解码。

正式入口显式装配真实 adapter；测试替身只属于测试构建，不提供环境变量、启动参数或设置项切换模拟实现。保持 ADR-0001、ADR-0005、ADR-0009、ADR-0012 约束：凭据存储身份与权限不变，业务装配仍在获得主实例资格后执行，应用级共享状态不因窗口关闭而重建，直接替换与不回退规则不变。测试使用非秘密样本、隔离凭据存储、临时文件根目录及独立偏好设置，不得误触真实登录项、全局快捷键、更新联网、系统权限请求或已有主实例。

组合测试需驱动生产原生控件和正式绑定的回调，观察窗口可见性、控件状态、外部请求和经公开接口读取的持久化结果；不得在测试里手写返回引导、发布成功或放行截图。必须覆盖验证前后、未选模型、正常选择、关闭/重开、迟到完成、恢复等待和活动终结。配置、截图、模型请求及重跑始终使用同一个活动所有者，禁止在测试装配中建立第二份协调状态。

应用重建测试必须重新创建应用、编辑和配置会话，仅保留约定的测试凭据存储及临时磁盘数据；它证明重建后的恢复，不证明真实进程崩溃或 Keychain 授权。程序化原生输入不等于物理快捷键送达，窗口可见性也不等于 macOS 前台激活。正式构建资源/签名身份检查与安装版物理交互继续独立验收，不被组合测试替代。

### Seam 2：Provider 适配器契约

双语新增验证复用既有三个 seam：以官方流封装的分块 fixture 验证三 Provider 片段解码、首段译文早于后段原文、Unicode 跨块及终态校验；真实 runner/临时 SQLite 验证映射原子保存、旧库迁移及重试保护；生产原生文本控件验证选择范围、双栏复制、流更新保留选区，并取得新构建界面渲染。录制及合成 fixture 不替代当前真实账户契约测试。

对 OpenAI、Gemini、DeepSeek 使用同一组契约测试，输入录制的官方协议响应与错误，验证完整分页、图片请求构造、统一流事件顺序、取消、三个超时、截断、usage 与错误归一化。DeepSeek 提取文字可把真实实验模型观测到的唯一 `text` 字段受限归一化为统一 `source` 事件；该兼容不适用于翻译、其他 Provider 或带额外字段的结果。另以受保护真实密钥运行发布门禁契约测试，分别报告提取与翻译，但不得把密钥、用户内容或原始响应写入产物。

### Seam 3：macOS 与持久化集成验收

用集成测试和签名产物验收覆盖多显示器冻结、当前进程排除、物理像素裁剪、TCC 权限恢复、全局快捷键冲突、Keychain、PNG 原子写入与哈希所有权、数据库迁移/故障保留、单实例、附着面板打开时的正常退出、Sparkle 架构 appcast、签名、公证和 Gatekeeper。工作区捕获准备与遮罩控制器分别验证失败回滚和原子替换；ScreenCaptureKit 合成后的进程排除效果必须在签名 App 中观察，不能由只验证过滤器构造的单元测试替代。Developer ID profile 解码、身份派生和 fail-closed 判定通过可重复的脚本契约测试覆盖；三架构最终 App 均验证嵌入 profile 与实际签名 entitlement 的一致性，Universal 最终签名 App 执行使用随机假凭据的 Data Protection Keychain CRUD，并在失败后仍尝试清理。纯视觉常量按已确认原型与截图做人工/快照核对，不为 CSS 式细节建立脆弱单元测试。

## Prototype Coverage

双语对照原型已确认：结果窗口与管理中心共用双栏样式，连续段落、同列复制图标、悬停/点击/文本选择对应高亮、对齐的标题/正文分隔线以及紧凑的重试/Pin/删除操作组。原型流式样本及结构样本仅验证展示和协议方向，不证明全部 Provider 真实账户兼容性。

历史页面已确认采用工具栏类型分段、Provider 下拉与搜索，180pt 应用导航、260pt 记录列表、首次以普通窗口铺满可用屏幕、扩大的详情、彩色类型/状态和右对齐时间，选中项无边框。用户要求同步上述已确认调整至原生 App；原型确认不替代当次原生产物的渲染与交互验收。显示器变化补验收不新增界面，沿用现有冻结/失效/退出状态。

已经确认的交互方向覆盖：完整原生 Edit 菜单、首次引导与隐私详情、首次引导跳转及自动返回、设置中心内联 Provider 折叠卡片与 API Key 行内状态、附着面板打开时的统一退出与取消退出状态、冻结选区操作栏、核心结果窗口及流式/失败状态、菜单栏第一入口、统一管理中心及历史类型筛选与搜索、截图时来源界面退让，以及历史记录单击选择、右侧详情内联重试且双击不打开新窗口。生产 AppKit/SwiftUI 界面必须保持这些原型的信息层级、控件清单、状态表达、视觉密度和明确确认的几何；原型 fixture 不得进入生产数据。

数据库恢复、权限被撤销和更新安装依赖 macOS/Sparkle 系统交互，不引入新的产品信息架构；实现前必须用窄状态原型或系统对话框验收稿验证其文案、主次操作和取消路径。它们不得改变本文定义的数据与恢复语义。

## Out of Scope

- Apple Vision OCR、传统 OCR 管线和 OCR 后文本翻译。
- 本地模型、Ollama、LM Studio、自定义 OpenAI-compatible 端点。
- 截图标注、划线、画框、贴图编辑、滚动截图和窗口自动识别。
- 结果手动编辑、坐标/字体/版面还原、自动写入剪贴板。
- 自动重试、自动 Provider/模型回退、请求级高级参数。
- 繁体中文目标语言、目标语言手动输入、RTL 界面镜像。
- 历史同步、应用内备份、导入既有图片、自定义截图目录。
- 自动清理此次修复前已产生的重复历史，或根据图片相同合并不同记录；既有用户记录不因本次重试修复而删除。
- 历史持久化提示词版本及为此新增数据库字段或迁移；内置提示词的内部标记不构成历史验收要求。
- 历史页面的状态、模型、目标语言、日期范围筛选及高级筛选面板；记录元数据和底层既有查询能力不因此删除。
- Mac App Store、Beta 更新通道、匿名遥测和费用估算。

## Further Notes

- 性能目标以交互路径衡量：快捷键触发后立即展示冻结帧与选区；网络请求在收到 Provider 首个有效文字事件后立即流式展示。10 秒是超时门槛，不是期望响应时间。
- Provider API 限制是签名、版本化的应用配置，不能从未签名远端动态改变。
- “原始 PNG”是截图保存、上传、哈希和历史所有权判断的统一字节对象。

Pending: 发布前必须使用当前官方文档与真实账户契约测试确认 OpenAI 和 DeepSeek 的图片请求体大小计算与限制，并写入签名版本化 Provider 配置；无法确认时，对应 Provider 不得标记为发布就绪。

Pending: `deepseek-v4-flash-vision-exp` 只有在当前账户的官方完整模型列表返回精确 ID，且真实密钥契约测试覆盖图片输入、流式结构、取消、超时、截断、错误映射和 usage 全部通过后才可发布；否则 DeepSeek 入口保持不可用或不随该版本发布，遵循 ADR-0011。
