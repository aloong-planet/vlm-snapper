# VLMSnapper v1 核心规格

状态：已完成需求对齐与设计审查；DeepSeek 发布就绪仍受本文 Pending 项约束。

## Problem

macOS 用户经常需要从屏幕局部内容中提取文字或获得翻译。现有工具通常依赖传统 OCR 后再翻译，或者拥有与任务无关的标注能力。VLMSnapper v1 要提供一条短、可预测且资源占用较小的路径：冻结快捷键触发瞬间的屏幕、选择矩形区域、保存原始 PNG，并由用户显式选择“提取文字”或“翻译”，将同一张原始截图直接交给在线视觉模型。

产品必须使网络发送、落盘、重试和清理行为对用户可理解且可控制。任何失败不得隐式重试、切换 Provider、改图或用残缺结果冒充成功。

## Solution

VLMSnapper 是原生 macOS 14+ 菜单栏应用。v1 接入 OpenAI、Gemini 和 DeepSeek 官方接口，通过统一 Provider 契约获取模型列表、发送图片请求、消费流式事件并归一化错误。应用不在 Dock 或 `⌘Tab` 中显示；菜单栏面板是日常第一入口，统一管理中心承载历史与设置。

截图快捷键触发时，应用先冻结所有可用显示器的当前帧，再允许矩形选区。用户确认选区后可在紧贴选区的操作栏中选择操作、目标语言和当前 Provider/模型。模型操作开始前，应用原子保存原始 PNG 并建立可恢复的历史记录；只有本地持久化成功且请求体未超过 Provider 限制，才允许上传。

文字提取使用一次多模态请求返回结构化 Markdown。翻译也使用一次多模态请求，直接从截图提取原文并返回原文与译文，不依赖已有提取结果。结果窗口保留原图、操作切换、只读结果、复制、取消、手动重试和重新执行能力。

## User Stories

### 1. 启动与单实例

- 作为用户，我启动 VLMSnapper 时，每个 macOS 用户只能有一个主实例负责菜单栏、全局快捷键、历史、清理和更新。
- 第二次启动只唤醒主实例：有活动结果时将其带到前台，否则打开菜单栏面板，然后退出自身。
- 关闭普通窗口只隐藏窗口，不退出应用；状态项右键菜单的“退出 VLMSnapper”或窗口激活时的 `⌘Q` 才退出。
- 左键点击状态项打开或关闭菜单栏面板；右键显示只含“退出 VLMSnapper”的原生菜单。主面板按确认原型显示 Provider 就绪状态、截图与当前快捷键、仅在新版本可用时出现的更新提示、三条带缩略图/操作时间/终态的真实最近记录，以及历史记录和设置中心双列入口，不重复放置退出或手动检查更新。Provider 配置、权限恢复或存储与隐私附着面板打开时也必须进入相同的正常退出流程，不能被 modal 状态静默取消。历史与设置打开同一个管理中心并定位到对应页面。
- 应用安装本地化的原生 macOS 主菜单。完整 Edit 菜单使用 AppKit responder chain 提供 Undo/Redo、剪贴板、Find、Spelling & Grammar、Substitutions、Transformations、Speech、Dictation 与 Emoji & Symbols；Provider API Key 与所有标准文本编辑表面都必须支持系统 Command-V，不实现字段专用粘贴旁路。

### 2. 首次引导与权限

- 首次引导同时呈现屏幕录制权限、Provider/当前模型和存储与隐私三个项目。
- 前两项是开始使用的必要条件；缺少任一项时按实际缺项说明原因并禁用“开始使用”。“稍后完成”始终可用，存储与隐私说明不作为阻断条件。
- 三个项目的操作按钮使用同一类次要描边样式。存储与隐私详情使用 8 px 圆角的连续扁平表面，按在线处理、本地保存、自动清理、备份与同步分区；只提供关闭，不提供设置跳转、同意复选框或面向用户的实现术语。
- 用户跳过引导后，首次触发截图才请求屏幕录制权限。授权成功提示重启并提供一键重启；拒绝或权限被撤销后只说明原因并提供系统设置入口，不重复弹出系统请求。
- 未配置可用 Provider/当前模型时，截图入口关闭菜单栏面板并把首次引导窗口带到最前；用户从居中的应用附着面板进入 Provider 配置，不启动屏幕冻结或系统权限请求。

### 3. 截图入口、全局快捷键与屏幕冻结

- 默认快捷键是 `⌥⇧S`，用户可在设置中通过按键录制控件修改。
- 保存快捷键前立即尝试注册；冲突或注册失败时显示具体错误并保留旧快捷键，成功后立即生效。
- 菜单栏面板的“截取屏幕”按钮与全局快捷键进入同一个截图工作流。点击面板按钮时始终先关闭面板；Provider 未配置或权限未就绪时把首次引导窗口带到最前并显示对应恢复入口，两项就绪时冻结屏幕。
- 截图工作流触发瞬间冻结每块显示器的当前帧。视频或动画选择期间继续播放，不影响最终截图；最终截图来自触发时的冻结帧。
- 各显示器独立冻结。单屏断开、休眠或捕获失败时，该屏不可选并显示原因，其他成功屏仍可使用；全部失败时退出选区且不创建历史。全局权限问题进入权限恢复流程。
- 选区只支持矩形，最小为 2 × 2 物理像素。无效选区保持在选择状态供用户调整；`Esc` 或取消退出且不保存。
- 选择开始后不接纳新出现的显示器；显示器断开或几何属性变化时，使对应冻结帧失效而不重新捕获实时画面。
- 原始 PNG 不包含鼠标指针、选区遮罩、尺寸标签、边框或操作栏；选区中的其他应用、菜单栏、Dock 和系统窗口按冻结帧原样保留。
- Retina 显示器按 ScreenCaptureKit 报告的 point-to-pixel 比例冻结物理像素帧；选区预览按逻辑尺寸显示，但冻结帧和最终 PNG 不降采样到逻辑 point 分辨率。
- 输出固定为 8-bit SDR、sRGB、原始 PNG，不转 JPEG、不缩放、不压缩、不做色彩增强。

### 4. 选区操作栏

- 确认选区后，截图内容固定不再变化。操作栏默认位于选区左下方 4 px，必要时移动以保持在可用屏幕内，但不移动选区或截图。
- 操作栏使用紧凑布局：3 px 内边距和控件间距、25 px 按钮高度、6 px 圆角。
- 操作栏提供“提取文字”“翻译”、目标语言、当前 Provider/模型和取消。目标语言只在翻译操作中生效。
- 任何模型调用只在用户点击“提取文字”或“翻译”后开始；此之前取消会丢弃内存截图且不创建历史。

### 5. 提取文字与截图翻译

- 提取文字把原始截图直接发给当前多模态模型，返回只读结构化 Markdown；不返回坐标、字体或像素级版面信息。
- 翻译把原始截图直接发给当前多模态模型，在一次请求中先返回从图片识别的原文，再返回目标语言译文；不得改成 OCR 后文本翻译或两个模型请求。
- 图片没有文字时，提取结果为空；翻译的原文和译文都为空，不生成图片描述或猜测内容。该操作仍作为成功记录保存并允许重新执行。
- 混合语言图片允许返回多个 BCP-47 源语言。源语言与目标语言相同时仍为成功，不追加第二次请求。
- 目标语言使用完整、可搜索的标准列表，优先展示简体中文、英语、日语、韩语、西班牙语、法语、德语、葡萄牙语、意大利语、俄语和阿拉伯语；不提供繁体中文和手动输入。
- 内置提示词使用英文并带版本号；温度使用 Provider 可表达的最小值或 `0`，推理/思考模式关闭或降至最低，不提供高级参数 UI。
- 每次显式操作恰好产生一个 Provider 请求。失败后不自动重试、切换 Provider/模型、改用非流式请求或降级为其他处理方式。

### 6. 流式返回与结果窗口

- Provider 适配器向应用输出统一事件顺序：提取为文字增量后元数据和完成；翻译为 `sourceDelta → translationDelta → metadata → completed`，原文与译文不交错。
- 首个有效文字事件超时与事件间停滞超时均为连续 10 秒无有效活动；单次请求总超时为 90 秒。DeepSeek 返回非空 `reasoning_content` 时，只刷新当前无活动计时，不显示、持久化或暴露该内容；可见文字开始前超时仍归类为首字超时，开始后仍归类为事件间停滞。OpenAI 与 Gemini 的活动判定保持不变。
- 应用不主动覆盖 Provider 的最大输出 token。Provider 明确达到输出长度上限、结构不完整或无法可靠解析时，本次操作失败，丢弃未完成流，不把残缺内容保存为正式结果。
- 结果窗口顶部固定“提取文字 / 翻译”切换。切换到已有成功、失败或取消结果只展示内容，不自动请求；从未执行的操作显示显式开始按钮。
- 同一时间全局只允许一个活动模型任务。任务进行时再次触发快捷键，只把当前结果窗口带到前台。
- 结果窗口首次打开或用户再次显式请求时带到前台，随后使用普通窗口层级；用户切换到其他应用后允许进入后台，流式内容刷新不得反复抢回焦点。请求中关闭窗口等同主动取消并保存取消状态；请求完成后关闭只隐藏。
- 结果工作区没有活动模型任务且没有未保存结果时，再次触发截图会先隐藏该窗口，再冻结当前屏幕并进入新选区；已经保存的旧结果仍可从历史记录查看。连续触发只接纳一次工作区退让，进入选区后继续沿用重新冻结当前帧的行为。活动请求或未保存结果不会被新截图替换，而是继续把当前结果窗口带到前台。
- 结果只读，可复制 Markdown，不自动写入剪贴板，不提供修改功能。
- 在仍打开的结果工作区点击 Try Again 属于当前结果重跑：复用该截图与操作的现有历史记录，先保留旧成功结果，只有新请求成功并完成最终持久化后才原子覆盖内容与本次模型元数据。新请求失败或取消时保留旧历史结果，并单独显示最近一次尝试状态。以后从管理中心发起的历史操作重跑属于新的操作记录，不改写原历史。

### 7. Provider 配置与模型发现

- v1 只支持 OpenAI、Gemini、DeepSeek 官方端点，不允许自定义 Base URL，不接入本地模型。
- 每个 Provider 独立保存 API Key、完整模型列表缓存和当前模型；应用另有一个全局当前 Provider。
- Provider 配置在首次引导或管理中心的居中应用附着面板中展示。API Key 粘贴或输入后立即启用“验证并获取模型”；只有鉴权成功且完整分页模型列表解析成功，才原子写入 Apple Keychain 并替换缓存；失败保留输入与旧配置。
- 模型列表接口返回 401/403 时必须明确显示 API Key 被拒绝，不得误报为 Provider 临时不可用；传输、5xx 或模型列表协议失败仍按其真实类别终止，均不自动重试。
- 验证成功后不跳转页面，而是在 API Key 区域下方展开当前模型选择框和刷新按钮。模型只能从列表选择，不支持手动输入。
- 首个完成配置的 Provider 仅在没有可用记忆选择时自动成为全局当前 Provider；随后配置的 Provider 不抢占当前选择。
- 打开 Provider 设置时先显示缓存；缓存缺失或超过 24 小时才自动刷新。用户可手动刷新；应用不在启动、后台或每次截图前刷新。
- 模型不可用错误会触发一次列表刷新。只有完整刷新成功才替换缓存；当前模型从列表消失时立即清除并要求重新选择，当前请求停止且不重复调用。
- 模型的图片能力状态为未知、已验证或不兼容。首次真实图片操作完成验证；只有可明确归类为不支持图片模态的错误才标记不兼容并清除当前模型，普通 HTTP 400 不足以改变状态。新 Key 或成功的新列表刷新把兼容状态重置为未知。
- 活动请求期间 Provider 配置只读：API Key、模型选择、清除配置和列表刷新均禁用；请求进入终态后恢复。
- API Key 按 ADR-0001 存入 Apple Keychain；稳定应用身份按 ADR-0005 使用 `com.loong.vlmsnapper`。
- API Key 验证成功但 Apple Keychain 写入失败时，Provider 不得被标记为已配置；应保留当前输入并显示本地安全存储错误，不得误报为 Provider 临时不可用。

### 8. 错误、限流与取消

- 所有 Provider 与本地错误映射为稳定的归一化类别。默认界面显示本地化原因和匹配的处理建议，不使用笼统“请求失败”。
- 至少区分网络、首次文字超时、流停滞、总超时、普通限流、额度/余额/套餐、鉴权、模型不存在或无权访问、图片模态不兼容、图片超限、内容安全、无效请求、响应不完整、输出截断和本地存储错误。
- 技术详情及复制内容只允许 Provider、模型、失败阶段、HTTP 状态、脱敏后的 Provider 错误码和 Request ID；不包含截图、原文、译文、API Key、认证头、原始请求或响应正文。
- 普通瞬时限流按 Provider 建立 1–5 分钟持久化冷却。有效 `Retry-After` 截断到该区间，无有效值时为 1 分钟；显示倒计时且不自动请求。其他 Provider 不受影响。
- 每日额度、余额、套餐或账户级配额错误不套用短冷却，直接建议检查账户或切换 Provider。
- 用户主动取消立即停止请求并保存“已取消”。应用启动时把遗留的准备请求、上传中或流式中操作终结为“意外中断”，丢弃残缺流但保留截图与请求元数据；两类状态分开显示和筛选，均只能由用户手动重新执行。
- 正常退出或 Sparkle 安装前主动取消当前请求，记录为“已取消”；未走完正常关闭流程的遗留任务才是“意外中断”。

### 9. 原始 PNG、历史与持久化顺序

- 模型操作使用并保存完全相同的原始 PNG 字节。文件保存于 `~/Pictures/VLMSnapper/YYYY-MM/`，命名为 `vlmsnapper-yyyyMMdd-HHmmss.png`；同秒冲突依次追加 `-2`、`-3`，绝不覆盖。
- 根目录和月份目录在首次模型操作保存时按需创建；“在 Finder 中显示”可创建根目录。v1 不提供自定义保存位置，也不跟随符号链接到其他位置。
- 内部数据库、结果、索引和日志位于沙盒 Application Support；分层存储遵循 ADR-0006，历史数据保护边界遵循 ADR-0002。
- 点击模型操作后，先原子写入 PNG、计算 SHA-256，再创建“准备请求”历史记录。两步均成功且请求体预检通过后才允许网络上传。
- PNG 保存失败时保留当前会话的内存截图并提供“重试保存”；关闭窗口或退出后丢弃，不创建历史。
- PNG 已保存但历史记录创建失败时，仅当文件是本次创建且 SHA-256 一致才回滚删除；无法回滚则作为孤儿文件保留，应用不自动认领或删除。
- Provider 已完成但最终数据库写入失败时，结果保留在内存并可复制；“重试保存”只重试数据库写入，不再次请求 Provider。关闭尚未保存结果前必须确认。
- 请求前按 Provider 的真实请求体计费方式检查图片大小。超限时不联网、不改图、不切换上传方式；保留截图和失败记录并显示实际大小、限制与缩小选区建议。
- 只有当前安装创建、且历史保存的路径与 SHA-256 均匹配的文件是受管理截图。用户移动、删除或替换图片后保留文字与元数据，但禁止显示、上传、重新执行或删除不匹配文件。
- 数据库不可用时阻止新的模型操作，但允许设置、诊断和 Finder 操作，并提供重试、导出可恢复数据、显示数据库位置和重置。重置前保留故障数据库副本，不静默重建，遵循 ADR-0008。
- 数据库架构比应用更新时只读阻断写入，提示更新应用或在保留旧库后重置。

### 10. 历史浏览与清理

- 管理中心标题栏左侧提供“全部 / 提取文字 / 翻译”筛选，右侧保留原文或译文搜索。还支持状态、Provider、模型、目标语言、日期和钉住筛选。管理中心的最小尺寸按 `920×620` 内容区约束，缩到最小时标题栏、列表底栏和详情内容均不得被窗口外框裁切。单击历史记录只更新当前详情；双击整条记录打开该记录对应的结果工作区，直接展示已保存内容且不自动请求 Provider，管理中心同时退到后台。若原始截图仍可用，用户之后可从结果工作区手动重跑并生成新的历史操作；截图不可用时仍展示已保存文字，但不允许重跑。
- 管理中心侧栏使用确认的浅层导航表面；历史详情在带描边的独立卡片中显示原始截图可用性、结果、Provider、模型、首字耗时、总耗时和 Provider 实际返回的 token usage；不估算费用。
- 默认保留期为 30 天，可选 7、30、60、90 或 180 天，不提供自定义值或永久保留选项。钉住记录不参与自动清理。
- 自动清理在启动后执行一次，此后最多每 24 小时一次。缩短保留期前显示将删除数量并确认，确认后立即清理；延长不触发清理。活动记录跳过。
- 删除是永久操作，不进入废纸篓且不可撤销。手动删除钉住记录必须确认；清空历史允许选择是否包含钉住项。批量删除遇到单项失败继续处理其他项，最后报告成功与失败数量。
- VLMSnapper 不同步历史。Time Machine、云盘或其他工具生成的外部副本不受应用清理保证。

### 11. 本地化、隐私与诊断

- v1 UI 支持简体中文和英语，默认跟随系统，允许手动切换；切换后要求重启。日期与数字仍遵循用户区域设置。
- v1 不制作 RTL UI 镜像，但结果内容必须正确显示双向文本。
- 不采集遥测。诊断日志只记录允许的时间、Provider、模型、阶段、耗时、HTTP 状态、脱敏错误码、脱敏 Request ID 和归一化错误类型，保留 7 天并支持用户导出。
- 面向用户的隐私说明表达为数据保存在这台 Mac、受 macOS 用户权限保护、API Key 在 Apple Keychain；不得把内部加密实现措辞直接展示给用户。

### 12. 更新与分发

- v1 仅通过 Developer ID 直接分发，不发布 Mac App Store，遵循 ADR-0007。
- 使用 Sparkle 稳定通道。自动检查默认开启，固定每 6 小时且只提供开关；不自动下载更新，也不提供自动下载开关。
- 发现新版本后在菜单栏和通用设置中提示，由用户显式开始下载。菜单栏与设置页监听同一应用级 Sparkle 状态，只有 Sparkle 确认下载完成后才显示“已下载”。下载完成不打断截图或模型任务，在退出时安装，也允许用户选择立即重启并更新；应用连续运行 7 天仍未安装时温和提醒一次。手动检查更新只在通用设置中提供。
- appcast 使用 HTTPS；应用和 DMG 通过 Developer ID 签名、Apple 公证与 stapling，更新包另有 Sparkle EdDSA 签名。
- Universal、Apple Silicon、Intel 分别打包并订阅独立 appcast，保持当前安装架构，遵循 ADR-0004。三个产物必须使用相同版本和 Sparkle 公钥；任一架构的签名、公证、stapling 或更新签名失败，整个版本不发布。
- 三个 Developer ID 应用必须嵌入同一份与 `com.loong.vlmsnapper` 匹配的分发 provisioning profile。正式签名从 profile 动态派生 App ID Prefix、Team ID、完整 application identifier 和精确 Keychain access group，不在仓库中硬编码账号前缀。
- provisioning profile 是仓库外的发布输入，不进入 Git。缺失、无法验签或解码、过期、分发渠道错误，或与 Bundle ID、Team ID、Developer ID Application 证书、Keychain allowlist 不一致时，正式流水线必须在签名前失败，不得回退到无 profile 或 legacy Keychain 构建。
- 最终已签名 App 必须声明 profile 授权的精确 application identifier、Team ID 和 Keychain access group。三个架构均做 profile/签名静态一致性验证；Universal 产物还必须由最终已签名的应用进程执行一次 Data Protection Keychain 的增、读、改、删验收。

## Failure Modes

以下按用户实际操作序列定义终态；更细的归一化错误类别仍遵循上文。

1. 用户通过快捷键或主面板按钮触发截图，但没有可用 Provider/模型：不请求屏幕权限、不冻结屏幕；按钮路径先关闭菜单面板，再把首次引导窗口带到最前并提供居中的 Provider 配置入口。
2. 用户通过快捷键或主面板按钮触发截图，但权限未授予或已撤销：不捕获，显示原因和系统设置入口；授权后要求重启；按钮路径先关闭菜单面板，再把首次引导窗口带到最前并展示权限恢复入口。
3. 部分显示器冻结失败：失败屏不可选，其他屏继续；全部失败则退出且无历史。
4. 用户拖出过小或跨越失效显示器的选区：保持选择模式，不生成 PNG。
5. 用户在模型操作前取消：释放内存截图，无文件、无历史、无网络。
6. 用户点击操作，但 PNG 无法保存：无网络，内存保留并允许重试保存；关闭后丢弃。
7. PNG 成功而准备记录失败：无网络；仅删除所有权和哈希均可证明的本次文件，否则保留孤儿。
8. 请求体预检超限：不联网、不改图，保存失败记录并建议缩小选区。
9. Provider 调用出现网络、超时、限流、鉴权、安全或协议错误：立即停止，不自动重试；丢弃残缺流并保存归一化失败。
10. Provider 明确模型不支持图片：失败并清除当前模型，标记不兼容；普通 400 不触发该变化。
11. 模型不存在：只刷新列表一次；确认消失则清除并终止，刷新失败保留旧缓存但本次仍失败。
12. 用户在请求中关闭结果窗口或主动取消：停止请求并保存已取消；不保留残缺文字。
13. 应用崩溃或断电后重启：遗留非终态变为意外中断，不自动恢复请求。
14. Provider 完成但最终结果落库失败：结果只驻留内存且可复制，只允许重试数据库保存；关闭前确认。
15. 用户移动、删除或替换受管理 PNG：保留文本和元数据，不显示、不上传、不删除不匹配文件。
16. 自动清理或批量删除部分失败：继续其余记录并汇总结果；不把失败项误报为已删除。
17. 历史数据库损坏或版本过新：阻止新模型操作和写入，不静默新建；保留恢复路径。
18. 更新准备安装时存在活动请求：先正常取消并持久化取消状态，再退出安装。
19. 应用附着面板打开时退出：仍进入统一退出协调；若未保存结果确认被取消，应用继续运行且原面板保持打开。
20. 用户验证有效 API Key，但当前已签名应用没有 Data Protection Keychain 授权或本地 Keychain 写入失败：验证流程终止，不保存 Provider 配置，显示本地安全存储错误及可操作建议，不改写为网络或 Provider 错误。
21. 发布者启动正式构建，但 provisioning profile 缺失、过期、损坏，或与应用身份、签名证书、Keychain allowlist 不匹配：在任何可发布产物签名或上传前终止，不留下可被误当成正式发布的降级产物。
22. provisioning profile 验证通过，但 profile 授权与最终 App 签名实际声明不一致，或 Universal 产物的 Data Protection Keychain CRUD 失败：整个三架构版本失败，不进入公证、分发或 appcast 发布。
23. 用户在结果工作区已进入成功、失败或取消终态且结果已安全保存后触发截图：先隐藏结果窗口，再冻结当前屏幕并进入选区；旧结果保留在历史记录中。
24. 用户在结果工作区仍有活动请求或未保存结果时触发截图：不替换工作区、不冻结屏幕，把当前结果窗口带到前台；同一工作区的退让请求只消费一次，不能与 Try Again 并发启动。
25. 用户在管理中心触发截图且当前允许开始新截图：先隐藏管理中心，再冻结屏幕并进入选区，管理中心不能出现在冻结帧中。
26. 用户单击管理中心历史记录：只切换详情；用户双击整条记录：管理中心退到后台并打开该记录的结果工作区，已保存结果立即显示且不产生网络请求或新历史记录。只有用户随后明确点击 Try Again 时，才按历史操作重跑规则创建新记录。

## Implementation Decisions

- 使用原生 Swift/SwiftUI 与必要的 AppKit 桥接实现 macOS 14+ 菜单栏应用；以 ScreenCaptureKit 捕获冻结帧，以系统安全存储保存密钥，以 Sparkle 负责直接分发更新。
- 以应用工作流状态机作为主协调边界：屏幕冻结、选区、内存截图、PNG 持久化、准备记录、Provider 请求、流式解析和最终持久化必须具有显式状态及唯一终态。
- Provider 抽象只暴露模型列表获取、图片请求事件流、取消和归一化错误，不把各厂商响应结构泄漏给结果 UI 或历史层。
- 原始 PNG 与历史记录采用分层所有权模型；删除权限由当前安装创建标记、保存路径和 SHA-256 三者共同决定。
- 全局活动任务、Provider 冷却、当前 Provider/模型和单实例身份均为应用级状态，不能由单个窗口生命周期拥有。
- 所有用户可见字符串进入本地化资源；代码、注释和模型提示词使用英语。
- 相关架构决策：ADR-0001 至 ADR-0011。其中 ADR-0006 修订 ADR-0002 早期的截图路径描述，当前实现以 ADR-0006 为准。

## Testing Decisions

### Seam 1：应用工作流契约

以不依赖真实窗口和真实网络的应用协调器公开行为为最高层 seam，验证从快捷键/选区/操作到成功、失败、取消、意外中断的状态转换，以及“先持久化、后上传”“单次点击单次请求”“旧成功结果只在新成功后覆盖”等不变量。该 seam 覆盖绝大多数用户操作序列和竞态。

### Seam 2：Provider 适配器契约

对 OpenAI、Gemini、DeepSeek 使用同一组契约测试，输入录制的官方协议响应与错误，验证完整分页、图片请求构造、统一流事件顺序、取消、三个超时、截断、usage 与错误归一化。DeepSeek 提取文字可把真实实验模型观测到的唯一 `text` 字段受限归一化为统一 `source` 事件；该兼容不适用于翻译、其他 Provider 或带额外字段的结果。另以受保护真实密钥运行发布门禁契约测试，分别报告提取与翻译，但不得把密钥、用户内容或原始响应写入产物。

### Seam 3：macOS 与持久化集成验收

用集成测试和签名产物验收覆盖多显示器冻结、物理像素裁剪、TCC 权限恢复、全局快捷键冲突、Keychain、PNG 原子写入与哈希所有权、数据库迁移/故障保留、单实例、附着面板打开时的正常退出、Sparkle 架构 appcast、签名、公证和 Gatekeeper。Developer ID profile 解码、身份派生和 fail-closed 判定通过可重复的脚本契约测试覆盖；三架构最终 App 均验证嵌入 profile 与实际签名 entitlement 的一致性，Universal 最终签名 App 执行使用随机假凭据的 Data Protection Keychain CRUD，并在失败后仍尝试清理。纯视觉常量按已确认原型与截图做人工/快照核对，不为 CSS 式细节建立脆弱单元测试。

## Prototype Coverage

已经确认的交互方向覆盖：完整原生 Edit 菜单、首次引导与隐私详情、Provider 配置附着面板、附着面板打开时的统一退出与取消退出状态、冻结选区操作栏、核心结果窗口及流式/失败状态、菜单栏第一入口、统一管理中心及历史类型筛选与搜索、截图前退让，以及历史记录单击选择和双击进入结果工作区。生产 AppKit/SwiftUI 界面必须保持这些原型的信息层级、控件清单、状态表达、视觉密度和明确确认的几何；原型 fixture 不得进入生产数据。

数据库恢复、权限被撤销和更新安装依赖 macOS/Sparkle 系统交互，不引入新的产品信息架构；实现前必须用窄状态原型或系统对话框验收稿验证其文案、主次操作和取消路径。它们不得改变本文定义的数据与恢复语义。

## Out of Scope

- Apple Vision OCR、传统 OCR 管线和 OCR 后文本翻译。
- 本地模型、Ollama、LM Studio、自定义 OpenAI-compatible 端点。
- 截图标注、划线、画框、贴图编辑、滚动截图和窗口自动识别。
- 结果手动编辑、坐标/字体/版面还原、自动写入剪贴板。
- 自动重试、自动 Provider/模型回退、请求级高级参数。
- 繁体中文目标语言、目标语言手动输入、RTL 界面镜像。
- 历史同步、应用内备份、导入既有图片、自定义截图目录。
- Mac App Store、Beta 更新通道、匿名遥测和费用估算。

## Further Notes

- 性能目标以交互路径衡量：快捷键触发后立即展示冻结帧与选区；网络请求在收到 Provider 首个有效文字事件后立即流式展示。10 秒是超时门槛，不是期望响应时间。
- Provider API 限制是签名、版本化的应用配置，不能从未签名远端动态改变。
- “原始 PNG”是截图保存、上传、哈希和历史所有权判断的统一字节对象。

Pending: 发布前必须使用当前官方文档与真实账户契约测试确认 OpenAI 和 DeepSeek 的图片请求体大小计算与限制，并写入签名版本化 Provider 配置；无法确认时，对应 Provider 不得标记为发布就绪。

Pending: `deepseek-v4-flash-vision-exp` 只有在当前账户的官方完整模型列表返回精确 ID，且真实密钥契约测试覆盖图片输入、流式结构、取消、超时、截断、错误映射和 usage 全部通过后才可发布；否则 DeepSeek 入口保持不可用或不随该版本发布，遵循 ADR-0011。
