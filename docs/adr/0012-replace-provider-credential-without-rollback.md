# ADR-0012: Provider 新凭据直接替换且不保留回退副本

- 状态: 已接受（2026-09-04）

## 背景与问题

已配置 Provider 允许用户直接输入新的 API Key。新 Key 可能在鉴权、模型列表获取或安全存储阶段失败，因此需要明确旧凭据在替换过程中的资格与失败后的 Provider 状态。

## 备选项

1. **提交新 Key 时立即移除旧凭据和旧配置，不保留回退副本**
2. 在新 Key 完整验证并持久化成功前继续保留旧凭据——否决，因为这会让用户明确提交替换后仍存在一份可恢复的旧秘密，并引入候选与生效凭据并存的状态

## 决策

选定**方案 1**：用户提交非空新 Key 后，旧 Key、旧模型缓存和该 Provider 的当前模型立即失去资格。任一步失败都保持该 Provider 未配置并保留当前输入供修正；应用不恢复旧凭据，也不让全局当前 Provider 继续指向它。

## 后果

- 正面：凭据状态只有一条清晰的生效路径，不需要持久化旧秘密或向用户解释隐式回滚。
- 负面：新 Key 验证失败时，原本可用的 Provider 也会变为未配置，用户必须修正并重新验证。
- 中性：如果新模型列表仍包含原先选择的模型，可以保留该模型选择；否则必须重新选择模型。另一个全局当前 Provider 不会被新配置抢占。

## 接受替换的边界（2026-09-06 补充）

用户确认：只有旧凭据作废记录成功持久化后，应用才接受替换。作废记录不含秘密，只标识失效的凭据版本；后续失败或重启不得恢复该版本。如果 Keychain 与普通配置存储同时无法写入，应用无法持久记录作废，因此拒绝接受本次替换，不发送验证请求，保留原配置并显示安全存储错误；存储恢复后允许再次读取原配置。这是接受替换的前置条件，不是在已接受替换后保留回退副本。
