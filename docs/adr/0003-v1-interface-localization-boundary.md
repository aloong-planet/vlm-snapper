# ADR-0003: 固定 v1 界面本地化边界

- 状态: 已接受（2026-08-25）

## 背景与问题

VLMSnapper v1 需要提供简体中文和英语界面，同时翻译结果可能包含阿拉伯语等双向文字。语言选择若把“跟随系统”解析成一次性快照，系统语言变化后应用不会继续跟随；如果把界面语言与区域格式混用，日期和数字会采用错误格式。完整 RTL 界面还需要镜像布局和重新验证截图操作栏定位，超出 v1 范围。

## 备选项

1. **UI 仅支持简体中文和英语，提供持续的“跟随系统”偏好，不承诺 RTL 界面镜像**
2. 只跟随系统且不允许用户覆盖——否决，因为用户可能希望应用语言与系统语言不同
3. v1 同时支持 RTL 界面语言——否决，因为需要镜像全部布局、物理方向属性和像素定位逻辑，显著扩大测试与维护范围

## 决策

选定**方案 1**：界面语言偏好取值为“跟随系统”“简体中文”“英语”，默认跟随系统。跟随系统时遍历 macOS 语言偏好列表并选择首个受支持语言，均不匹配时回退英语；偏好本身持久化，解析出的生效语言不持久化。手动切换语言后重启应用生效。

简体中文是源文案，英语字典从其形状派生；日期、时间和数字格式独立跟随 macOS 区域设置。产品 UI 不承诺 RTL 镜像布局，但模型结果使用系统双向文字排版显示。运行时值、日志字段和持久化枚举使用语言无关的英文标识。

## 后果

- 正面：语言行为稳定、可测试；用户可以持续跟随系统或显式锁定语言；日期和数字不会因 UI 语言覆盖而采用错误区域格式。
- 负面：阿拉伯语等语言只能作为结果内容显示，不能成为 v1 的界面语言；语言切换需要重启应用。
- 中性：实现前必须在项目能力声明中登记语言集和字典位置；编译期字典形状检查与源码文案扫描门禁分别覆盖漏译和漏抽，并需要证明门禁能够失败。
