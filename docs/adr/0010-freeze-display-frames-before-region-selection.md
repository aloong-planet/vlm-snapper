# ADR-0010: 快捷键触发时冻结屏幕帧再选区

- 状态: 已接受（2026-08-25）

## 背景与问题

VLMSnapper 支持在所有显示器上进入矩形选区。视频、动画、加载状态和快速变化的界面可能在用户拖拽期间改变；如果到鼠标松开才截图，最终 PNG 会与用户开始截图时看到的内容不同。另一方面，提前捕获所有显示器会产生短时内存开销，需要明确资源生命周期。

## 备选项

1. **快捷键触发时捕获并冻结所有显示器，再从冻结帧裁切选区**
2. 用户开始拖拽时捕获所在显示器——否决，因为快捷键触发到拖拽之间画面仍可能变化
3. 用户松开鼠标后再截图——否决，因为最终图片可能不是用户选区时看到的动画帧

## 决策

选定**方案 1**。按下截图快捷键或点击截图按钮时立即捕获所有显示器当时的画面，选区界面基于冻结帧显示。用户完成矩形后，从对应显示器的初始冻结帧裁切原始 PNG，不再次捕获实时屏幕。

捕获时不先隐藏 VLMSnapper 窗口，也不等待窗口动画。应用优先取得 `SCShareableContent.currentProcess`，并只使用同一快照中的当前进程应用对象和显示器对象构造排除当前进程的内容过滤器；该快照不能同时解析当前进程和显示器时，整批回退到一份全局 `SCShareableContent` 快照，仍只混用该快照内部的对象。无法解析当前进程时整次捕获失败关闭，不允许退化为包含自身窗口的截图。

全部可用冻结帧完成后，应用先建立新的不透明 `.screenSaver` 级选区遮罩并确认至少覆盖一个显示器，再一次性替换旧遮罩，最后只退下本次触发前明确记录的菜单栏面板、管理中心、结果工作区或旧操作栏。重复截图不预先销毁旧选区；冻结或新遮罩建立失败时，旧选区或结果工作区继续有效。

冻结帧和最终 PNG 不包含鼠标指针或 VLMSnapper 自己的遮罩、标签、边框和操作栏；其他应用、菜单栏、Dock 和系统弹窗按捕获瞬间的屏幕内容保留。第一版没有倒计时或延迟截图。选区取消或裁切完成后立即释放未选显示器及冻结帧资源。

最终 PNG 保留选区原始像素尺寸，但统一编码为 8-bit SDR sRGB。保存到 Pictures 和发送给 Provider 的是完全相同的 PNG 字节；不转换 JPEG、不做有损压缩、锐化或增强。第一版不提供 HDR、Display P3、色彩空间或位深切换。

多显示器冻结按显示器独立执行。单块屏幕断开、休眠或捕获失败时仅禁用该屏幕，其他成功冻结的屏幕仍可选择；全部失败才退出。全局屏幕录制权限错误继续走权限引导。已经冻结的显示器后来断开时释放其缓存，不取消其他屏幕的选区流程。

冻结帧以显示器 ID 和显示器本地像素坐标为边界。选区期间某屏的分辨率、缩放或旋转改变时只使该屏失效并取消其拖拽；其他未变化屏幕继续。新接入屏幕本次没有冻结帧，因此到下次快捷键触发前不可选。

有效选区在鼠标松开后立即固定并裁出内存 PNG，不提供拖动、缩放或重新选择。裁切完成后释放全部全屏冻结帧，只保留选中 PNG；操作栏可以移动，但不改变截图区域。

选区固定后，内存 PNG 保持显示在原位置，选区外使用不可交互的半透明暗色遮罩；底层应用继续运行。空白左键和右键不改变状态，`Esc`、关闭按钮或再次按截图快捷键才丢弃。再次按快捷键会捕获新帧重开选区；模型任务开始后则只唤醒结果窗口。

## 后果

- 正面：动画和视频截图与快捷键触发瞬间一致，选区预览与最终 PNG 不漂移。
- 正面：选区过程不需要持续录屏，也不在鼠标松开时再次等待系统截图。
- 负面：每次触发都需要短时持有所有显示器的全分辨率冻结帧，高分辨率多屏环境会出现瞬时内存峰值。
- 负面：依赖 `SCShareableContent.currentProcess` 后，最低系统版本提升为 macOS 14.4。
- 负面：HDR 或 Display P3 画面转换为 SDR sRGB 后，极亮区域和部分颜色可能与屏幕观感略有差异。
- 中性：多屏冻结不是全有或全无；用户可能看到个别屏幕不可选，但仍可在其余屏幕完成截图。
- 中性：冻结只影响 VLMSnapper 的选区视觉；其他应用本身继续运行和播放。
