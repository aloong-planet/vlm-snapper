# ADR-0014: 吸附区域只取自屏幕窗口列表，不使用辅助功能接口

- 状态: 已接受（2026-10-28）

## 背景与问题

用户希望截图时像 Snipaste 一样自动选中鼠标所在的区域：终端、浏览器等取整个窗口，Dock 上取单个应用图标。Snipaste 2.7.2 的静态逆向显示，它用屏幕窗口列表按前后顺序命中窗口，再用辅助功能接口（`AXUIElementCopyElementAtPosition`）取得窗口内或 Dock 中的界面元素；本机实测该接口对 Dock 应用可返回单个图标的框架。VLMSnapper 按 ADR-0006、ADR-0007 启用 App Sandbox，历史数据库位于沙盒容器内，而 Apple 明确不支持沙盒应用使用辅助功能接口。

## 备选项

1. **只用截图触发时取得的屏幕窗口列表确定吸附区域：整窗、菜单栏状态图标或菜单栏、Dock 条带整体、桌面为整块显示器；不识别单个 Dock 图标或窗口内元素**
2. 退出 App Sandbox 并申请辅助功能权限，识别单个 Dock 图标与界面元素——否决：需要推翻 ADR-0006、ADR-0007 的沙盒决定，迁移沙盒容器内的历史数据库，首次引导新增一项系统权限；用户于 2026-10-28 选择保留沙盒。
3. 保留沙盒，同时声明辅助功能接口并在授权后使用——否决：Apple DTS 说明沙盒应用不支持辅助功能接口，授权提示不出现、调用无法完成。
4. 按冻结帧图像分析或读取 Dock 偏好推算单个 Dock 图标的位置（未留档，业界常规备选）——否决：放大、间距、分隔符与最近使用应用使推算不可靠，读取其他应用偏好在沙盒中同样受限。

## 决策

选定**方案 1**。我们在截图触发时于主线程外取得一份按前后顺序排列的屏幕窗口列表，排除 VLMSnapper 自身、透明、离屏与系统覆盖层级的窗口，按鼠标位置在本地命中吸附区域。Dock 的全屏窗口不参与命中，Dock 所在条带由显示器全幅与可用区域之差得出并作为一个整体区域。不调用辅助功能接口。

## 后果

- 正面：保持 ADR-0007 的沙盒安全边界与 ADR-0006 的数据位置，不新增系统权限；吸附结果与冻结帧来自同一时刻，命中不依赖其他进程的响应。
- 负面：用户在 Dock 上无法直接选中单个应用图标，窗口内的按钮、侧栏等元素也不能单独吸附，需要手动拖选。
- 负面：Dock 设为自动隐藏时没有固定条带，Dock 区域按其下方的窗口或桌面处理。
- 中性：窗口列表在签名沙盒应用中的可用性与几何需在安装版上实测；若将来要求单个图标或元素，须先另立 ADR 处理退出沙盒与数据迁移。

## 来源

- Snipaste 2.7.2 截图链路静态逆向报告“选择框怎样自动套住窗口”（REA 6.5.0 调 Ghidra 12.1.4；本机材料，未入库）
- 2026-10-28 本机实测：未沙盒进程对 Dock 应用的 `AXUIElementCopyElementAtPosition` 返回单个 `AXDockItem` 及其框架；窗口列表中 Dock 为 layer 20 全屏窗口，菜单栏为 layer 24、状态项为 layer 25 的独立窗口
- [Apple Developer Forums 794253](https://developer.apple.com/forums/thread/794253)：DTS 说明“We do not support the Accessibility APIs in sandboxed apps.”
- [Apple Developer Forums 810677](https://developer.apple.com/forums/thread/810677)：沙盒应用无法获得辅助功能授权
