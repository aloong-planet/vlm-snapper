# ADR-0015: 在截图界面内显示模型结果，弃用独立结果窗口

- 状态: 提议

## 背景与问题

用户点击“提取”或“翻译”后，应用先撤下选区遮罩，再打开独立结果窗口，用户要离开截图现场，到另一个窗口查看原图与结果。用户参考飞书的截图取字与翻译，决定让结果留在截图现场。结果留在遮罩之上，意味着遮罩与冻结帧的生命周期要延长，读结果期间屏幕也一直被遮罩占据。

## 备选项

1. **开始操作后保留遮罩、选区和操作栏，结果流式显示在遮罩之上的结果框中，退出截图时一起关闭，弃用独立结果窗口**
2. 保留独立结果窗口——否决：用户仍要离开截图现场，这正是要解决的问题。
3. 退出遮罩后把结果框留在屏幕上作为浮窗——否决：相当于保留一部分独立窗口的生命周期，还要新定浮窗层级、多个浮窗并存、下次截图是否拍入、请求是否在后台继续。
4. 开始操作后只保留所选显示器的遮罩，其他显示器恢复可用——否决：点到其他显示器后键盘焦点离开截图界面，Esc 与 ⌘C 都要先点回来才有效。

## 决策

选定**方案 1**。开始提取或翻译后，我们锁定选区，保留操作栏，并在独立于选区的结果框中流式显示结果；同一时间只显示一个结果框。所有显示器的遮罩与冻结帧、以及显示器变化监听，都保留到退出截图。退出截图时结果框随遮罩一起关闭，请求进行中退出等于取消。

我们删除独立结果窗口。模型请求的准入、“先持久化后上传”的顺序、单次请求、重跑的记录身份规则，以及管理中心历史页都不变。

本决策修订 ADR-0010 中“模型任务开始后则只唤醒结果窗口”的决定，以及冻结帧释放时机：冻结帧不再在开始操作时释放，而是保留到退出截图。冻结时机、裁切来源与排除 VLMSnapper 自身的决定不变。

## 后果

- 正面：结果与原图同屏，用户不用切换窗口；应用少维护一套结果窗口的生命周期。
- 负面：读结果期间其他 App 不可操作，请求也不能放到后台继续；要边看边操作其他 App，只能先复制结果或退出后到历史页查看。
- 负面：全部显示器的全分辨率冻结帧占用内存的时间延长到退出截图，占用量尚未实测。
- 负面：结果框要在不激活应用的 `.screenSaver` 级面板中支持选中文字和 ⌘C，这在安装版上尚未实测；验证通过后本 ADR 才升级为已接受。
- 中性：截图界面只显示译文，原文与译文的逐句对照保留在历史详情。

## 来源

- 2026-11-03 需求对齐对话：方案 2、3、4 的取舍由用户在对话中选定。
- 飞书的做法依据用户描述；公开资料未找到其截图取字与翻译的说明，也未读过其实现。
- 冻结帧释放时机与现有窗口接线来自当时代码的核对；内存占用与面板层级、⌘C 行为待实测。
