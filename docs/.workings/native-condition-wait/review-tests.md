# 原生测试等待：测试自审

## 维度 1：覆盖

- 等待契约四项：立即已满足；稍后满足且只等到满足；始终未满足且最后间隔小于 10 ms；零预算的满足/未满足两种结果。
- 保留历史 5 项：初次详情、Provider 筛选、窗口查询生命周期、组合查询与选择、双语言/双主题/双尺寸渲染。
- 保留 Provider 7 项及原参数化输入：关闭草稿、恢复旧 Key 不提交、危险输入、粘贴语义、输入/Return/刷新、其他 Provider 活动占用、指定 Provider 焦点导航。
- 保留菜单按钮两项：完整区域触发、hover 状态。
- 测试使用既有假 Key、历史 fixture、真实生产 UI；本轮不新增外部数据格式解析，不需另外伪造 Provider 响应。

## 维度 2：用例设计

- 时间是允许注入的系统边界。契约测试使用可控时钟，避免对真实机器耗时设置 10 ms 性能断言而制造 flaky。
- 历史断言仍看渲染行和选中像素，Provider 仍走 AppKit 编辑及公开验证回调，未改成私有状态设置或直接业务触发来凑绿。
- 保留原有业务断言的含义；相同的行数/选中/几何断言移入会抛错的等待，不再在紧随其后重复截图断言。没有放宽上限、条件跳过或吞错。
- 新 helper 不进入产品模块；不是为测试给生产代码新增可配置的等待参数。

## 维度 3：假通过核查

- 固定等待实现下，“已满足立即返回”真实红：虚拟耗时为 0.1，期望为 0；命令退出 1。
- 10 ms 实现下四项全绿。
- 独立变异：把生产于测试 target 的暂停间隔改为 50 ms 并重新构建；实际采样序列 `[0, 0.05]` 不等于 `[0, 0.01, 0.02]`，两项共三条断言红，退出 1。随后只撤销该单行变异。
- 正向 UI 等待直接使用目标状态。负向提交是已核实的同步回调检查；不把“暂时没发生”当成异步安全结论。
- 合成 AppKit 输入不等于真实物理鼠标/VoiceOver 验收；AX 回归也不替代真实 Provider 和 Keychain 验收。本轮不声称覆盖这些边界。
