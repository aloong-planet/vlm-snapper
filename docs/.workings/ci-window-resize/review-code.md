# 代码自审

## ① 底层前提

发现并修正：固定 1100pt 宽度不能作为所有桌面的合法用户调整尺寸。CI 1024pt 宽与本机超屏复现均在重新显示后收窄。新 fixture 通过当前屏幕的 contentRect（含标题栏换算）选择屏幕内尺寸；不使用延时或放宽相等断言掩盖变化。

## ② 可运行性

定向原生测试退出 0。尺寸设置后先验证实际 content size、屏幕包含关系，以及确实小于首次铺满框架。桌面不足以容纳有效调整时显式 XCTFail，避免静默跳过。defer 仍关闭测试窗口。无新增并发、外部依赖或资源持有。

## ③ 安全正确性

只改测试 fixture，不访问用户历史、Keychain 或屏幕内容，不改生产权限和窗口逻辑。故障只导致本用例明确失败，不污染其他记录或应用数据。

## ④ 一致性

保留 US-001/AC-17 的首次铺满、非独立全屏、隐藏/切页后严格保持框架三项断言。变异生产 hasPresented 分支后最后一项正确变红；仅撤销该变异，生产文件最终无 diff。

同类检查：对 Tests 全目录显式检索 setContentSize/setFrame，共 4 处设置调用。其余 3 处分别测试最小 content、920×620 Provider 布局、应用测试 hosting fittingSize，不用超屏固定尺寸作隐藏后框架保持的期望；不需同改。另检查 hideForCapture 调用，其余查询保留/应用生命周期测试不依赖硬编码尺寸。未发现此次改动引入需重构项。
