# VLMSnapper v1 需求对齐记录

> 状态：需求讨论过程记录，尚未合成为正式 spec。

## 产品与平台

- 产品展示名为 `VLMSnapper`，仓库名为 `vlm-snapper`。
- v1 直接分发版本的 Bundle Identifier 固定为 `com.loong.vlmsnapper`；Keychain service、登录项、屏幕录制权限和 Sparkle 身份均以其为稳定根标识。
- Universal、arm64 和 x64 三个构建共享同一 Bundle Identifier，只允许架构和 appcast 地址不同；正式发布后不得随意修改该身份。
- 第一版是原生 macOS 菜单栏应用，目标最低系统为 macOS 14。
- 应用不显示 Dock 图标，也不出现在 `⌘Tab` 应用切换列表中；打开历史或设置窗口时也不临时显示 Dock 图标。
- 菜单栏面板是日常第一入口，提供截图、最近记录、历史记录、设置中心、检查更新和退出；已打开窗口可通过对应入口再次带到前台。
- 点击菜单栏面板中的“历史记录”或“设置中心”均打开同一个管理中心窗口，只分别定位到历史页或设置页，不创建两套独立窗口外壳。
- 关闭窗口不退出应用；通过菜单栏“退出 VLMSnapper”或窗口激活时按 `⌘Q` 才彻底退出。
- 第一版不提供标注、划线、画框等截图编辑功能。
- 第一版不使用 Apple Vision OCR，也不接入本地模型。
- 界面支持中文和英文。
- UI 语言仅支持简体中文和英语；设置提供“跟随系统（默认）”“简体中文”“English”。
- “跟随系统”遍历 macOS 语言偏好列表并选择首个受支持语言；都不匹配时回退英语。语言偏好持久化，“跟随系统”解析出的当前生效语言不持久化。
- 手动修改 UI 语言后提示重启应用并提供一键重启；日期、时间和数字格式独立跟随 macOS 区域设置。
- 简体中文是 UI 源文案，英语从中文派生；代码标识符、日志字段和持久化枚举使用语言无关的英文标识。
- 项目源代码和代码注释统一使用英文；项目设计与需求文档可继续使用中文。
- 产品 UI 不承诺 RTL 镜像布局；阿拉伯语等翻译结果仍使用系统双向文字排版显示。
- 实现时使用编译期语言字典形状检查和源码文案扫描门禁，分别阻止漏译与漏抽。

## 截图与操作

- 全局区域截图快捷键可自定义，默认值为 `⌥⇧S`。
- 没有可用 Provider 时按截图快捷键不进入截图选区，也不触发屏幕录制授权；显示简短原因和“配置 Provider”按钮。用户完成配置后需要重新按快捷键开始截图，不保留此前的屏幕帧或内存截图。
- 快捷键使用按键录制控件配置，不允许手动输入字符串；必须包含 `⌘`、`⌥` 或 `⌃` 中至少一个修饰键，`⇧` 可附加但不能单独使用。
- 禁止单字母、数字、方向键、`Esc`、`Return` 等容易干扰正常输入的组合。
- 保存快捷键前立即尝试注册；注册冲突或失败时显示错误并保留旧快捷键，成功后立即生效，无需重启。
- 设置页提供“恢复默认”，恢复为 `⌥⇧S`。
- 第一版只支持鼠标拖拽矩形区域截图，不提供窗口自动识别、点击窗口截图或全屏截图模式。
- 拖拽选区时显示选区尺寸，按 `Esc` 取消。
- 单击但未形成面积时不截图，也不解释为全屏截图；裁切后的物理像素宽或高小于 2 像素时视为无效选区。
- 无效选区不保存、不显示操作栏也不调用模型，继续停留在选区模式供用户重新拖拽；只要至少为 `2 × 2` 物理像素就允许完成，不设置更大的最小尺寸，按 `Esc` 才退出整次截图。
- 鼠标松开形成有效选区后立即固定区域并裁出内存 PNG；第一版不提供拖动选区、缩放手柄或“重新选择”。
- 裁切完成后立即释放所有全屏冻结帧，只保留选中 PNG；选错时关闭操作栏或按 `Esc` 丢弃，再触发快捷键捕获新的实时帧。
- 多显示器环境下，快捷键触发后所有显示器都进入选区状态，用户可在任意一块显示器上拖拽。
- 单次选区必须位于一块显示器内，不允许跨显示器边界；各显示器分别按自身 Retina 缩放比例处理截图像素和坐标。
- 按下截图快捷键时立即捕获并冻结所有显示器当时的画面；用户随后看到并拖拽的是冻结帧，视频和动画不随选区过程继续变化。
- 最终原始 PNG 从快捷键触发时的冻结帧裁切，不在鼠标开始拖拽或松开完成选区时重新截图。
- 原始 PNG 不包含鼠标指针，也不包含 VLMSnapper 自己的选区遮罩、尺寸标签、边框或操作栏；选区内其他应用窗口、macOS 菜单栏、Dock 和系统弹窗按冻结帧实际内容正常保留。
- 第一版不提供倒计时或延迟截图；取消选区或完成裁切后立即释放未选中显示器和冻结帧的临时图像资源。
- 多显示器冻结按显示器独立执行；单块显示器断开、休眠或捕获失败时，该屏幕显示不可选遮罩和“无法捕获此显示器”，其他成功冻结的显示器仍可继续选区。
- 所有显示器都捕获失败时退出选区，不保存历史并显示捕获错误；如果失败原因是全局屏幕录制权限，则进入既定权限引导，不归类为单屏故障。
- 显示器在成功冻结后断开时释放该显示器缓存，其他成功显示器继续可选。
- 冻结帧按显示器 ID 和显示器本地像素坐标保存，不依赖可能变化的全局桌面坐标。
- 某块显示器在选区期间改变分辨率、缩放比例或旋转时，只使该屏冻结帧失效；正在该屏进行的拖拽取消，其他未变化显示器继续可选。
- 选区期间新接入的显示器没有快捷键触发瞬间的冻结帧，本次不可选，下次重新触发快捷键才加入；最终没有任何可用显示器时退出选区并提示重试。
- 完成区域截图后显示操作栏，提供“提取文字”和“翻译”两个操作。
- 选区完成后的操作栏允许移动以避免遮挡，但移动操作栏不改变已经固定的截图区域。
- 选区固定后，选中的 PNG 继续显示在原位置并保持冻结内容；选区外只保留半透明暗色遮罩，底层应用可继续变化但在遮罩期间不能接收点击。
- 点击选区外空白区域不取消也不重新开始选区，第一版不为右键设置额外行为；只有 `Esc`、操作栏关闭按钮或再次按截图快捷键才丢弃当前截图。
- 选区或操作栏阶段再次按截图快捷键时，立即丢弃当前内存 PNG、捕获新的冻结帧并重新进入选区；模型任务开始后再次按快捷键仍只把当前结果窗口带到前台。
- 用户点击操作后才调用模型。
- 浮动结果窗口顶部始终保留“提取文字 / 翻译”切换栏；切换到已有成功、失败或取消结果时只显示该结果，不自动调用模型。
- 切换到从未执行过的操作时显示操作说明和明确的“开始提取”或“开始翻译”按钮；重新执行已有操作必须点击独立的“重新执行”，重复点击标签不得触发请求。
- 模型请求期间允许切换查看另一操作的已有结果，但另一操作的“开始/重新执行”按钮禁用，直到当前任务结束。
- 两种子操作分别保存自己的 Provider、模型、状态、耗时和其他请求元数据；同一截图允许由不同 Provider 分别完成提取和翻译。
- 启动尚未执行的第二种操作时使用当时全局选中的 Provider 和模型；翻译还使用结果窗口当时选择的目标语言。
- 截图完成后、尚未点击“提取文字”或“翻译”时，按 `Esc` 或关闭操作栏会丢弃本次截图，不写入历史记录。
- 选区完成后使用单行底部贴附式操作栏：操作栏外边框与选区外边框之间保持实际可见的 `4px` 间距，并与选区左边缘对齐；始终直接显示“提取文字”“翻译”、目标语言、当前 Provider/模型和取消。操作栏使用 `3px` 内边距和按钮间距，按钮高度为 `25px`，操作栏及其中按钮圆角统一为 `6px`；按钮本身不使用外边距。
- 点击模型操作后退出截图遮罩，并将操作栏展开为可移动、可调整大小的浮动结果窗口。
- 浮动结果窗口采用已确认的 AC 混合卡片工作台：保留卡片式原始截图与结果区域，窗口顶部中央使用原生分段控件切换“提取文字 / 翻译”，不采用贴边检查器布局。
- 工作台主体左侧为原始截图卡片，右侧为当前操作的结果卡片；顶部右侧显示当前 Provider、模型和目标语言。切换到“提取文字”时隐藏目标语言，切换已有结果不自动请求。
- 结果卡片标题栏保留当前结果类型与复制操作；底部状态栏显示请求状态、Provider 和既定耗时指标。深浅外观跟随 macOS，演示原型中的状态与主题切换条不属于产品界面。
- 请求期间和结果展示期间，浮动结果窗口保持在普通窗口上方，点击其他应用不会自动关闭。
- 请求过程中关闭结果窗口等同主动取消并保存“已取消”记录；请求完成后关闭窗口只隐藏界面，结果仍保存在历史中并可从菜单栏重新打开。
- 第一版全局只允许一个活动任务：同一时间只能存在一个截图选区或一个正在执行的模型操作，不提供任务队列或并发请求。
- 模型操作进行中再次按截图快捷键时不启动新截图，而是将当前结果窗口带到前台；用户取消当前任务后可立即开始新截图。
- 当前任务完成后，即使结果窗口仍开着也允许开始下一次截图；历史重执行遵守同一活动任务限制，历史浏览和复制不受限制。
- 模型操作进行中 Provider 设置页仍可查看，但所有 Provider 的 API Key 新增、修改或删除、模型选择、配置清除和模型列表刷新都暂时禁用；请求成功、失败或取消后立即恢复。其他不影响 Provider 请求身份的普通设置仍可修改。
- 文字提取把截图直接交给当前模型，返回截图中的原始文字。
- 模型明确判断截图中没有可读文字时视为成功空结果，不重试；界面显示“未发现可读文字”。
- 无文字时“提取文字”结果为空，“截图翻译”的原文和译文均为空，禁止用图片描述或猜测内容代替文字。
- 无文字结果仍保存截图和操作记录，并允许用户改用其他模型重新执行。
- 原文保留标题、段落、换行、列表和表格等逻辑结构，并按最可能的阅读顺序输出；表格使用 Markdown 表格。
- 第一版不提取文字坐标、字体、颜色或边界框，也不追求像素级版面还原。
- 截图翻译把原始截图和翻译指令直接发送给当前视觉模型，由模型在一次多模态请求中完成读图、提取原文和翻译，并同时返回原始文字与目标语言译文。
- 截图翻译不依赖已有的“提取文字”结果，也不拆分为“先提取、再发送纯文字翻译”两次模型请求。
- 译文尽量保持与原文一致的段落、列表和表格结构。
- 截图翻译的源语言由模型自动识别，不要求用户选择。
- 翻译响应返回检测到的源语言列表，内部使用 BCP-47 代码；结果页在原文栏显示本地化语言名称。
- 混合语言截图中，所有非目标语言文字翻译为目标语言，已经是目标语言的部分保持不变。
- 只有截图中的全部文字都已是目标语言时才提示“原文已是目标语言”；无法可靠判断时显示“未知”，但原文和译文结构完整则仍视为成功。
- 单独的“提取文字”操作不要求检测或显示语言。
- 截图操作栏提供目标语言下拉菜单；切换目标语言不触发请求，只有点击“翻译”时才使用当前选择。
- 记住用户最后选择的目标语言；首次默认值跟随应用界面语言，中文界面为简体中文，英文界面为英文。
- 目标语言选择器置顶简体中文、英语、日语、韩语、西班牙语、法语、德语、葡萄牙语、意大利语、俄语和阿拉伯语，并提供可搜索的完整标准语言列表。
- 目标语言内部使用稳定的 BCP-47 语言代码；第一版不允许自由输入语言名称。
- 第一版不提供繁体中文目标语言选项，中文目标只提供简体中文。
- 语言列表只表示应用可向模型提出该翻译目标，不承诺所有模型对每种语言的翻译质量相同。
- 当模型判断源语言与目标语言相同时，仍返回统一的原文与译文双栏结构；译文保持与原文相同，并提示“原文已是目标语言”。
- 源语言与目标语言相同不视为错误，也不发起第二次请求。
- 结果采用流式呈现；截图翻译的一次响应固定先输出原文，再输出译文。
- Provider adapter 向应用统一输出 `sourceDelta → translationDelta → metadata → completed` 事件；文字提取只产生原文相关事件，截图翻译必须等原文完成后才开始译文，禁止交错输出。
- Provider 可使用不同 SSE、JSON 或 SDK 协议；支持原生 JSON Schema 时优先使用 schema。DeepSeek 若没有原生 schema，可使用内置英文提示词和固定边界标记，由 adapter 增量解析为统一事件。
- JSON 语法、边界标记和其他传输协议内容不得显示给用户；完整响应只有通过终态、非截断、完整解析、结构和领域校验后才可持久化。
- 格式或边界解析失败时立即停止并保存失败状态，不自动重试、不保存残缺结果，也不降级为两次请求、非流式请求或其他模型；用户可在查看具体原因后主动重试。
- “提取文字”和“截图翻译”使用应用内置、版本化的英文提示词；第一版不允许用户编辑系统提示词或输出格式模板。
- 翻译提示词唯一可变参数是目标语言；每条结果只记录提示词版本号，不重复保存完整提示词。
- 应用升级提示词后不改写旧历史结果；手动重新执行时使用当前版本提示词。
- 文字提取与截图翻译默认关闭模型的 thinking/reasoning 模式；无法关闭时使用 Provider 支持的最低推理档位。
- temperature 使用 `0` 或 Provider 支持的最低值；Provider 不支持某个参数时不发送该字段。
- 第一版不向用户开放 temperature、reasoning effort、top-p 等高级模型参数。
- 第一版不设置跨 Provider 的统一输出 token 上限，使用当前模型自身的默认输出限制；提示词要求只输出截图实际文字及所需译文，不添加解释。
- Provider 明确返回达到输出长度上限时判定为确定性截断错误，不自动重试，也不把残缺流式文字保存为正式结果。
- 截断操作保存失败状态，并提示用户缩小截图范围或选择输出能力更大的视觉模型。
- 原文先流式写入原文栏，原文结束后译文再流式写入译文栏；“同时返回”指单次请求产出两类结果，不要求两个区域并行生成。
- 响应缺少任一部分、格式不完整或无法可靠分隔时视为本次请求失败，立即说明原因并等待用户决定是否重试。
- “提取文字”结果提供一键复制；“翻译”结果的原文栏和译文栏分别提供复制按钮，并提供“复制全部”。
- 一键复制默认写入 Markdown 原文以保留标题、列表和表格结构；用户选中文字后按 `⌘C` 时只复制选中内容。
- 第一版不自动写入剪贴板，避免覆盖用户原有内容。
- 第一版的模型原文和译文结果均为只读；允许选择和复制文字，但不允许直接编辑。
- 历史记录保存模型原始返回内容，不区分或保存用户修改稿；结果不满意时通过重新执行覆盖。

## Provider 与模型

- 第一版内置 OpenAI、Gemini 和 DeepSeek 三个 Provider，并抽象统一 Provider 边界。
- 第一版三个 Provider 只连接各自官方 API Endpoint，设置页不提供自定义 Base URL、代理网关或 OpenAI-compatible 自定义服务。
- API Key 只发送到对应 Provider 的官方域名；Provider 抽象保留未来扩展自定义 Endpoint 的能力，但不进入 v1。
- 每个 Provider 分别配置 API Key、获取模型列表并保存自己的当前模型。
- 新增 API Key 时，先仅在内存中使用它获取完整模型列表；只有验证成功后才写入 Keychain。
- API Key 验证期间若发生鉴权、网络、响应解析或分页失败，不写入 Keychain，保留输入内容并允许重试。
- 修改已有 API Key 时，在新 Key 验证完成前保留旧 Key、旧模型缓存和当前模型；验证成功后再原子替换 Keychain 条目、模型缓存及当前模型状态。
- 新 Key 返回的完整模型列表若不含原当前模型，替换 Key 后同时清除当前模型，要求用户重新选择。
- API Key 验证成功并完整获取模型列表后立即保存 Key 和模型缓存，不要求用户在同一流程中选定模型。
- 尚未选择当前模型的 Provider 进入“待选择模型”状态；允许关闭设置页后再继续配置，但在选定模型前不能用于截图处理。
- Provider 只有同时具备已验证的 API Key 和有效当前模型时才进入“可用”状态。
- 应用全局只维护一个当前 Provider；截图操作栏显示当前 Provider 和模型，并可通过下拉菜单切换其他可用 Provider。
- 记住用户最后一次选择的当前 Provider，后续截图默认沿用。
- 全新安装或当前没有可用的已记忆 Provider 时，第一个完成 API Key 验证、选定模型并进入可用状态的 Provider 自动成为当前 Provider；以后新增或恢复其他 Provider 不得自动抢占当前选择。
- “待选择模型”或配置失效的 Provider 不进入操作栏的可用 Provider 列表。
- 当前 Provider 失效时不自动切换或回退；禁用提取文字和翻译操作，并引导用户选择或配置 Provider。
- API Key 使用 Apple Keychain 保存；OpenAI、Gemini、DeepSeek 使用彼此独立的 app 专属条目，并禁用同步。
- app 配置只保存 Provider 状态、当前模型和模型列表刷新时间等非秘密元数据，不保存 API Key 明文或密文。
- 删除 Provider 或清除配置时同步删除对应 Keychain 条目；日志、崩溃报告、历史记录和配置导出不得包含 API Key。
- DeepSeek v1 视觉候选采用 `deepseek-v4-flash-vision-exp`；该模型由用户确认可通过官方 `https://api.deepseek.com/models` 按账户返回，并已在同一官方 Endpoint 成功接收图片，但公开文档当前尚未收录，因此按账户可见的实验模型处理。
- VLMSnapper 不假设所有 DeepSeek 账户都能使用该模型；只有完整刷新官方模型列表且当前账户实际返回该 ID 时才允许选择，不手动注入、预选或通过自定义 Endpoint 补齐。
- 发布前必须使用受保护的真实 DeepSeek Key 对该模型执行契约测试，覆盖图片输入、流式响应、规定输出结构、取消、超时、截断、错误映射和 usage；测试失败时不得把 DeepSeek 标记为发布就绪。
- 每个 Provider 第一版只选择一个当前模型；文字提取和截图翻译共同使用它，不再分别选择视觉模型与语言模型。
- 获取 Provider 的完整模型列表，默认优先显示根据官方目录和名称规则推测出的视觉模型。
- 模型选择器提供“显示全部模型”，但不提供手动输入；当前模型必须来自 Provider 成功返回的完整模型列表。
- 选择模型时不发送测试图片；第一次实际操作时验证模型能否接收图片。
- 模型视觉兼容状态分为“未知”“已验证”“不兼容”；来自完整列表且未被明确判定不兼容的模型允许选择，第一次真实图片请求成功后标记为“已验证”。
- 第一次或后续真实操作若 Provider 明确返回“该模型不支持图片输入”，不执行模型重试；保存失败记录，将该模型标记为“视觉不兼容”，清除当前模型并要求重新选择。
- 视觉不兼容模型仍显示在“全部模型”中，但禁用选择并标注原因；成功刷新完整模型列表或更换 API Key 后，将对应不兼容状态重置为“未知”，允许再次选择验证。
- 只有 Provider 可明确归类为图片模态不支持的错误才改变兼容状态；普通 HTTP `400`、无效请求或响应格式错误不得误判为模型不支持图片。
- API Key 新增或修改并保存后，立即刷新对应 Provider 的模型列表。
- 打开设置页或切换 Provider 时先显示缓存；缓存不存在或超过 24 小时才自动刷新。
- 设置页提供手动刷新按钮；应用启动、后台定时和每次截图前都不刷新模型列表。
- 实际请求返回“模型不存在”或“无权访问”时，立即刷新一次模型列表。
- 只有完整获取所有分页且整个刷新成功，才能用新列表替换缓存并判断当前模型是否仍然存在。
- 成功列表中不存在当前模型时清除当前模型，要求用户重新选择；刷新失败时保留原模型和旧缓存。
- 因模型不可用错误触发刷新并确认当前模型已消失后，立即停止当前操作，不再重复请求该模型。
- 每次用户点击“提取文字”“翻译”“重试”或“重新执行”只允许向当前 Provider 的当前模型发送一次请求；任何失败都不得由应用自动重试，也不得自动切换 Provider 或模型。
- 网络中断、请求超时、HTTP `408`、`429`、`5xx`、流式响应中途断开、响应格式不完整、鉴权失败、图片超限、内容安全拒绝、无效请求、模型不存在或无权访问等错误都立即终止本次请求并保存失败状态。
- 失败界面必须说明可识别的具体原因，不能只显示“请求失败”；至少区分网络、超时、限流、鉴权、模型不可用、图片不兼容、图片超限、内容安全、无效请求、响应不完整或截断，以及本地存储错误，并给出与原因匹配的下一步建议。
- 错误默认层使用当前界面语言显示简洁的原因和处理建议；可展开的“技术详情”显示 Provider、模型、失败阶段、HTTP 状态码、Provider 错误码和 Request ID，但只显示 Provider 实际返回且经过脱敏的字段。
- 错误界面提供“复制错误详情”；复制内容与技术详情遵守同一脱敏规则，不包含原始请求或响应、截图、原文、译文、API Key、认证头或其他凭据。
- 失败历史记录持久化归一化错误类别、用户可读建议、失败阶段、HTTP 状态码、Provider 错误码和 Request ID；可选技术字段只在实际返回且脱敏后保存，并与该历史记录遵循相同保留、手动删除和自动清理规则。
- 历史详情继续提供同样的错误原因、脱敏技术详情和“复制错误详情”；不持久化仅为构造错误界面而临时读取的原始 Provider 错误正文。
- 流式请求中途失败时立即丢弃该次未完成文字，不保存为正式结果；界面显示错误原因和用户主动“重试”入口，新的手动请求从空白结果重新开始。
- 请求失败后默认保留刚才使用的 Provider 和模型选择；用户可以直接点击“重试”，也可以先在结果窗口切换到其他可用 Provider 或模型。
- “重试”始终使用点击时当前选中的 Provider 和模型，每次只发送一个请求；原模型已经从完整模型列表中消失或被标记为视觉不兼容时，必须先选择其他可用模型才能重试。
- 收到普通瞬时限流且 Provider 返回可解析的 `Retry-After` 时，错误界面显示“建议在 X 后重试”和实时倒计时；应用不在倒计时结束时自动发起请求。
- 普通限流冷却固定约束在 1–5 分钟：Provider 建议时间低于 1 分钟时按 1 分钟，高于 5 分钟时按 5 分钟，位于区间内时采用实际建议时间。
- 倒计时结束前禁用同一 Provider 的“重试”，即使切换该 Provider 内的模型也不能绕过；用户切换到其他已配置且可用的 Provider 后可以立即手动重试。
- 普通瞬时限流未携带有效 `Retry-After` 时默认冷却 1 分钟，仍落在统一的 1–5 分钟区间；显示倒计时且不自动发起请求。
- 能明确识别为每日额度耗尽、余额不足、套餐限制或账户级配额不可用时，不套用 1–5 分钟普通限流倒计时；直接说明具体原因，并提示检查额度、充值、调整套餐或切换 Provider。
- `Retry-After` 冷却截止时间按 Provider 持久化到普通应用配置，不写入 Keychain；配置只包含 Provider 标识和截止时间，不保存错误响应正文或其他请求内容。
- 应用重启后如果截止时间尚未到达，继续显示倒计时并禁用该 Provider 的手动重试；时间到达后自动清除该冷却状态，不自动发起请求。
- 请求开始后正常显示“正在上传截图”或“模型正在识别”；10 秒内未收到首个流式文本时判定超时，不另设“响应较慢”提示。
- 流式输出开始后连续 10 秒没有新内容时判定超时；首个文本超时、流式无内容超时和 90 秒单次请求总超时都立即报错，不自动重试。
- 单次尝试无论是否持续输出，总时长最多 90 秒；第一版不向普通用户开放这些超时参数。
- 用户在模型操作开始后主动取消时立即停止当前请求；保留原始截图，并将该操作记录为“已取消”而非失败。
- 已取消操作可从历史详情重新执行；用户在点击任何模型操作前取消时仍直接丢弃截图。
- 应用启动时扫描遗留在“准备请求”“上传中”或“流式返回中”等非终态的操作，将其终结为独立最终状态“意外中断”；保留原始 PNG、Provider、模型和目标语言，不保存此前的残缺流式文字。
- “意外中断”表示应用崩溃、强制退出、断电或其他未完成正常关闭流程的终止，与用户主动“已取消”分开显示和筛选；历史详情提供手动重新执行。
- 启动恢复不得自动续传或重新调用 Provider，因为无法确认服务端是否已经完成旧请求，自动重调可能重复计费。
- Sparkle 更新和正常退出必须先主动取消当前请求并记录为“已取消”；只有未走完该关闭流程的遗留操作才归类为“意外中断”。
- 从历史详情手动重新执行某个操作时直接覆盖该操作的旧结果，第一版不保留或展示结果版本历史。
- 重新执行期间暂时保留旧成功结果；新请求成功后才原子替换旧结果，新请求失败或被取消时保留旧成功结果并显示最近一次执行状态。
- 如果该操作原本没有成功结果，重新执行失败或取消后正常保留对应的失败或取消状态。
- 从历史详情重新执行时默认使用应用当前选中的 Provider 和模型，而不强制使用旧结果对应的模型；执行前允许切换其他可用 Provider。
- 重新执行成功并覆盖结果后同步更新该结果的 Provider 和模型元数据；失败或取消且旧成功结果被保留时，旧结果保留原元数据，并另行显示最近一次尝试使用的 Provider、模型及状态。
- 旧结果使用的模型已不可用时不阻止用户改用当前模型重新执行。
- 历史中的翻译操作重新执行时默认沿用该记录原来的目标语言，并允许执行前修改；成功覆盖后更新为新目标语言。
- 在历史详情修改目标语言不改变新截图操作栏记住的全局目标语言。
- 用户每次主动重试都属于一次新的显式执行；应用不会在同一次执行内部追加请求。残缺的流式文字不作为正式结果保存。

## 保存与历史

- 本地保存截图的原始无损 PNG；发送给 Provider 的也是同一份原始 PNG，不缩放、不转换为 JPEG、不做有损压缩。
- “原始 PNG”保留选区的原始像素尺寸和内容，但颜色统一输出为 8-bit SDR sRGB；HDR 或 Display P3 画面允许在转换后与屏幕观感存在轻微差异。
- 保存到 Pictures 与发送给 Provider 的必须是完全相同的 PNG 字节；第一版不提供 HDR、Display P3、色彩空间或位深切换，不做锐化、增强或其他图像处理。
- 每个 Provider adapter 在上传前构造最终请求体，并按 Provider 的真实计量方式执行大小预检，而不是只检查原始 PNG 文件大小。
- Gemini 对 Base64 图片、提示词、系统指令和 JSON 在内的完整 inline 请求体计量，必须严格小于 20 MB；OpenAI 按官方图片请求限制和所选模型特有限制检查。
- DeepSeek 实验视觉模型的大小限制必须由发布前真实契约测试确定并写入版本化 Provider 配置；限制未确定前不得标记 DeepSeek 发布就绪。
- 超限时不发送任何网络请求、不压缩、不改图、不切换文件上传接口；仍保存原始 PNG 和失败记录，并显示实际 PNG 大小、Provider 限制和“缩小截图范围”。
- Provider 限制变更只能随签名应用更新修改本地版本化配置，不从远程下载未签名规则。
- 图片超限属于确定性错误，不执行模型请求，但仍按失败状态保存截图及操作记录。
- 用户点击“提取文字”或“翻译”后保存截图和对应结果；失败操作也保留记录及失败状态。
- 用户触发模型操作后必须先将原始 PNG 原子写入截图目录，保存成功后才允许上传给 Provider；磁盘空间不足、目录不可写等本地保存错误不得发送截图。
- PNG 保存失败时保留当前截图的内存副本并显示具体存储错误和“重试保存”；用户修复本地问题后可在当前会话直接重试，无需重新截图。关闭当前窗口或退出应用后丢弃未保存的内存截图，不创建历史记录。
- 上传前还必须成功创建状态为“准备请求”的历史记录，并写入 PNG 路径和 SHA-256；只有 PNG 与该记录均成功持久化后才允许调用 Provider。
- PNG 已保存但“准备请求”记录创建失败时，不上传截图；若该 PNG 是本次刚创建且 SHA-256 一致，立即删除它以回滚。内存截图继续保留并提供“重试保存”。
- 如果上述回滚删除失败，显示本地存储错误并提供“在 Finder 中显示”；该 PNG 仍视为孤儿文件，不得生成有效历史记录或由后续自动清理误认领。
- Provider 已成功返回完整结果但最终结果写入历史数据库失败时，不得重新调用模型；完整结果保留在当前结果窗口内存中，正常提供复制按钮，并显示“结果尚未保存”和“重试保存”。
- “重试保存”只重试本地数据库写入，不重新上传截图、不产生新的模型费用；保存成功后恢复为正常历史记录。
- 未保存结果存在时，关闭窗口、退出应用或安装更新必须确认，并提供“复制全部”“取消关闭”和“仍然关闭”；用户仍然关闭后丢弃未落库文字，但保留 PNG 与预先创建的记录，下次启动将该操作标记为“结果保存失败”，允许用户重新执行。
- 原始 PNG 固定保存到用户可见目录 `~/Pictures/VLMSnapper/`；应用通过系统 Pictures 目录 API 定位该目录并使用 `com.apple.security.assets.pictures.read-write` entitlement，不硬编码用户主目录路径。
- `VLMSnapper` 根目录下按截图创建时的本地年月建立单层 `YYYY-MM/` 子目录，例如 `~/Pictures/VLMSnapper/2026-08/`；不使用 `YYYY/MM/` 两层目录。
- 原始 PNG 基础文件名固定为 `vlmsnapper-yyyyMMdd-HHmmss.png`，例如 `vlmsnapper-20260825-143012.png`；日期时间取截图创建时的本地时间，不包含毫秒、随机码、截图文字、Provider、模型或语言。
- 如果基础文件名已存在，按 `-2`、`-3` 依次追加编号，例如 `vlmsnapper-20260825-143012-2.png`；文件名必须通过原子创建占用，绝不覆盖或改写任何同名现有文件。
- 用户手动删除 `VLMSnapper` 根目录或当前 `YYYY-MM/` 目录后，下次保存时自动重新创建，无需确认。
- 如果预期根目录或年月目录位置是普通文件、符号链接，或解析后的路径离开系统 Pictures 目录，应用拒绝保存和上传，不覆盖、不删除也不跟随该路径，并显示存储错误和“在 Finder 中显示”；第一版不通过符号链接变相支持自定义保存位置。
- 应用安装、首次启动和首次引导均不预建空截图目录；用户第一次触发模型操作并进入上传前保存阶段时，才创建 `~/Pictures/VLMSnapper/` 根目录和当前 `YYYY-MM/` 目录。
- 如果根目录尚不存在，而用户在设置页点击“在 Finder 中显示截图目录”，则当场只创建并打开根目录，不预建年月目录；创建失败时显示本地存储错误。
- Pictures entitlement 虽提供整个系统 Pictures 目录的读写能力，但 VLMSnapper 不扫描、不索引也不读取 `~/Pictures` 的其他内容，应用逻辑只访问自己的 `VLMSnapper/` 子目录。
- 即使 `~/Pictures/VLMSnapper/` 在首次运行前已经存在，也不自动导入或认领其中的 PNG；只有由当前安装创建、且内部数据库同时记录路径与 SHA-256 的 PNG 才是受管理截图。
- 重装应用或清除 App Sandbox Container 后，目录中遗留的 PNG 保持普通用户文件，不重建历史且不参与自动清理；新截图与其同名时继续使用递增编号避让。
- 第一版不提供修改截图保存目录或迁移图片的功能；设置页提供“在 Finder 中显示截图目录”按钮，并显示解析后的真实用户路径，不暴露 Sandbox Container 中的代理路径。
- 历史数据库、模型返回的原文与译文、搜索索引、操作状态和日志保存在 App Sandbox Container 内的 `Library/Application Support/VLMSnapper/`，不向用户展示为独立文档。
- 保存原始 PNG 时同时在内部历史中记录该文件的 SHA-256；后续显示、重新执行、手动删除和自动清理前均以该摘要确认路径上的文件仍是原始截图。
- 用户从 Finder 删除或移动原始 PNG 后，保留原文、译文和元数据，图片区域显示“原始截图已被移动或删除”；已有文字仍可查看、搜索和复制，但依赖原图的重新提取与重新翻译不可用。
- 如果原路径出现 SHA-256 不同的文件，视为原图已被替换；应用不得显示、上传、覆盖或删除该文件，历史详情显示原图不可用。此后手动删除历史记录时只删除内部记录，自动清理也不得处理该替代文件。
- 从菜单栏面板可进入管理中心的历史页，以图片与文字双栏形式浏览并搜索。
- 历史页在窗口标题栏下方使用独立内容工具栏：操作类型筛选左对齐，搜索框右对齐；历史列表和详情从工具栏下方开始。设置页复用同一管理中心外壳。
- 历史搜索覆盖原文和译文内容，并支持按操作类型、最终状态、Provider、模型、目标语言、日期范围和钉住状态筛选。
- 历史搜索与筛选完全在本地执行，不向模型或其他服务发送历史内容。
- 结果窗口和历史详情显示 Provider、模型、首个文本耗时和总耗时。
- “首个文本耗时”从本次用户点击操作开始，到该次请求产生第一段可用文字为止；“总耗时”从同一次点击开始计算到该次请求成功或失败为止。用户主动重试是新的执行，耗时重新计算。
- Provider 为该次请求返回 token usage 时保存并显示输入、输出和总 token；未返回时显示“不可用”，应用不自行估算，也不跨用户主动重试汇总。
- 第一版不根据 token 用量计算金额。
- 第一版不对本地历史做应用层加密：截图 PNG 和文字数据库均以普通文件保存；PNG 位于 `~/Pictures/VLMSnapper/`，其余内部数据位于 App Sandbox Container，并受当前 macOS 用户权限约束。
- API Key 继续只存储在 Apple Keychain；不写入截图文件、历史数据库或普通配置。
- 第一版不启用 iCloud 或其他云端历史同步，也不主动上传历史内容；只有用户触发模型操作时，对应原始截图才发送给当前 Provider。
- VLMSnapper 不为原始 PNG 设置禁止备份属性，也不检测、阻止或绕过 Time Machine、企业备份、云盘或其他第三方同步策略；用户可见截图可能依照系统和用户配置被复制到其他位置。
- 隐私说明使用准确措辞：“VLMSnapper 不主动同步历史；截图可能依照你的 macOS、备份或第三方同步设置被复制到其他位置。”自动清理只删除当前 Pictures 目录中的受管理截图，不承诺删除已经进入外部备份或同步位置的副本。
- 本地历史的磁盘整体加密依赖用户是否启用 FileVault；获得该用户账户或磁盘访问权限的主体可能读取历史内容。
- 引导页和 Provider 设置页以非阻塞、面向用户的说明文字告知：点击模型操作后原始截图会发送给当前在线 Provider；截图和文字记录保存在这台 Mac 上，并受 macOS 用户权限保护；API Key 存储在 Apple Keychain 中。界面不直接展示“应用层加密”等实现术语，真实安全边界仍以本节内部要求为准。
- 第一版不要求用户勾选或确认该说明，不因未确认而禁用模型操作，也不在每次请求前重复弹窗。
- 自动清理期限固定提供 7、30、60、90、180 天五档，默认 30 天；第一版不提供自定义天数或“永不清理”。
- 首次引导页和自动清理设置需明确说明：`~/Pictures/VLMSnapper/` 中未钉住的原始 PNG 会随对应历史记录按保留期限永久删除。
- 期限按截图记录的创建时间计算，重新执行或查看记录不会延长保留期。
- 被钉住的记录不参与自动清理；“钉住”只表示保护历史记录，不表示把结果窗口钉在桌面上。
- 单条历史记录手动删除后立即永久处理，不提供 10 秒撤销，也不移动到 macOS 废纸篓；删除整条记录时同时删除匹配的受管理截图 PNG、提取结果、翻译结果和错误信息。
- 如果摘要一致的受管理 PNG 删除失败，则保留内部历史记录并显示删除失败，不得先删数据库记录造成用户无法重试；原图已经缺失或被替换时只删除内部记录，不触碰替代文件。
- 钉住的记录仍可手动删除，但删除前必须确认。
- “清空历史”必须先显示确认框和将删除的记录数量，默认保留钉住记录；用户明确勾选“同时删除钉住记录”后，确认框同步显示额外数量并一并删除。
- 确认清空后立即永久删除，不进入废纸篓且不提供撤销。批量过程中某条受管理 PNG 删除失败时保留该条历史并继续处理其他记录；不回滚已经成功删除的记录。
- 清空完成后报告成功和失败数量，失败记录继续显示并允许用户重试删除。
- 历史数据库损坏或版本迁移失败时，禁用提取文字和翻译，不允许绕过上传前历史记录门槛调用模型；Provider 设置、普通设置和“在 Finder 中显示截图目录”仍可使用。
- 数据库故障界面提供“重试打开”“导出诊断日志”“在 Finder 中显示数据目录”和“重置历史数据库”，应用不得自动删除、覆盖或静默重建损坏数据库。
- 用户确认重置后，将原数据库改名保存为带时间戳的恢复文件，再创建空数据库；重置会丢失应用内的文字结果、索引和历史记录，但保留 `~/Pictures/VLMSnapper/` 中的全部 PNG。
- 重置后遗留 PNG 因缺少新数据库中的路径和 SHA-256 记录而成为普通用户文件，不自动导入、认领或清理；数据库恢复文件不自动删除，恢复界面提供手动永久删除。
- v1 不维护每日或滚动历史数据库备份；数据库使用事务和 SQLite WAL，避免用户已经删除的文字仍长期残留在周期性副本中。
- 只在执行数据库 schema 迁移前创建临时备份；迁移成功、重新打开并通过完整性检查后立即删除该临时备份，迁移失败时才将其保留为带时间戳的恢复文件并进入数据库恢复页。
- 用户安装的旧版检测到数据库 schema 高于自身支持范围时，以只读方式阻断，不尝试自动降级或写入；禁用截图模型操作和历史修改，并显示“此历史由更新版本的 VLMSnapper 创建”。
- schema 过新界面提供“检查更新”“退出”和“在 Finder 中显示数据目录”，优先引导用户安装兼容的新版本；用户若坚持使用旧版，只能显式执行“重置历史数据库”，仍先把新版数据库保存为恢复文件，再创建旧版空数据库。
- 正在执行模型请求的活动记录不可手动删除，删除按钮暂时禁用；用户需要先取消当前任务，才能删除该记录。
- “清空历史”不取消当前模型任务，自动跳过活动记录，并在结果中报告跳过数量。
- 自动清理会永久删除过期且未钉住的记录，不提供撤销。
- 自动清理和用户缩短保留期限时同样跳过活动记录，不删除其 PNG 或数据库状态；活动操作结束后不立即补删，等待下一次正常清理检查，避免结果刚完成就从界面消失。
- 后台自动清理遇到文件占用、磁盘错误或数据库错误时，不弹模态窗口也不发送 macOS 通知；删除失败的记录继续保留，并在下一次正常清理检查自动重试。
- 存在清理失败时，菜单栏“历史”显示非阻塞警示点，历史页显示失败数量并提供“立即重试清理”和“查看诊断日志”；失败项全部清理成功后自动移除警示。
- 自动清理发现原始 PNG 已缺失或被替换时不计为清理失败：删除对应内部记录，不触碰同路径的替代文件。
- 手动删除或自动清理移除某月最后一张受管理 PNG 后，仅当对应 `YYYY-MM/` 目录完全为空时删除该月目录；目录中存在任何其他文件或子目录时原样保留，不判断或清理用户放入的内容。
- `~/Pictures/VLMSnapper/` 根目录永不由自动清理或手动历史删除操作移除。
- 应用启动后检查一次自动清理；应用持续运行时每 24 小时最多再检查一次，不做高频后台扫描。
- 用户缩短保留期限时，先显示将被永久删除的记录数量；确认后立即应用新期限并清理，取消确认则保持原期限不变。
- 用户调长期限时立即保存新设置，但不触发清理。

## 分发与生命周期

- 开发阶段仓库保持私有；v1 发布前再单独决定是否公开以及采用何种许可证，当前不作开源承诺。
- 每个 macOS 用户同时只允许一个 VLMSnapper 主实例运行；第二实例启动后不读取或修改历史数据库、不注册全局快捷键、不执行自动清理或更新检查，只通知现有主实例后立即退出。
- 主实例收到第二次启动通知时，若存在活动模型任务则将当前结果窗口带到前台，否则展开菜单栏菜单；异常退出留下的实例锁必须允许下一次启动安全回收。
- Universal、Apple Silicon 和 Intel 构建共享应用身份；即使用户并行安装多个架构，也只运行最先启动的主实例。
- 首次引导页显示 macOS 屏幕录制权限状态和“授予权限”按钮，但不在用户操作前自动触发系统授权框。
- 首次引导采用单页准备清单；点击其中的“配置 Provider”后，在引导窗口上打开附着式配置面板，不另开管理中心窗口。引导中的配置面板与设置中心复用同一套 Provider 配置内容和状态语义。
- 屏幕录制权限和至少一个已选当前模型的可用 Provider 是首次引导中开始使用的两个必要条件。任一项缺失时，“开始使用”保持禁用，并根据实际缺项动态说明原因；两项均完成后立即启用。用户始终可以选择“稍后完成”退出引导，存储与隐私说明不参与阻断。
- 点击“存储与隐私”的“查看详情”后，在首次引导窗口内打开与引导窗口相同字体、颜色和信息密度的扁平分区附着面板；面板使用单一连续表面，不把在线模型处理、本地保存、自动清理和外部备份/同步四个主题包成卡片。该面板不要求同意确认，也不提供设置跳转，只能通过关闭按钮、遮罩或 `Esc` 退出。目录路径等短信息与所属正文同行呈现，不为标签和值制造不必要的换行。
- 准备清单三项右侧的“授予权限”“配置 Provider”和“查看详情”统一使用同一套次级描边按钮样式，不因第三项是说明入口而降低其可点击性表达。
- Provider 附着式配置面板四个角统一使用 `8px` 圆角。
- 附着式配置面板依次完成 Provider 选择、API Key 验证与完整模型列表获取、当前模型选择。验证成功但尚未选择模型时允许关闭面板，清单显示“待选择模型”，入口改为“继续配置”；选择有效当前模型并点击“完成”后自动关闭配置面板、返回首次引导清单，清单显示“配置完成”以及 Provider 和模型名称，入口改为“修改配置”。
- API Key 验证成功后不把密钥区域替换成模型页面；原密钥区域保持可见，并在其下方直接展开当前模型选择框。模型选择框和刷新操作在同一控制行，帮助文字单独位于下一行；窄宽度下 Provider 标识保持固定盒尺寸，不发生收缩或错位。
- 附着式配置面板关闭、取消或验证失败时保留首次引导，不自动进入截图；用户仍可跳过引导并以后从设置中心继续。API Key 的写入时机、失败保留行为、模型来源和视觉能力验证继续遵循统一 Provider 规则。
- 用户跳过引导后，第一次使用截图快捷键时再触发系统授权；授权成功后提示重启 VLMSnapper，并提供一键重启按钮。
- 用户拒绝或之后撤销权限时，截图快捷键只显示原因和“打开系统设置”，不反复触发系统请求；权限恢复并重启后自动恢复截图功能。
- Provider 配置、历史浏览和设置页不依赖屏幕录制权限。
- 第一版不接入用户行为分析、崩溃自动上报或第三方遥测 SDK。
- 本地诊断日志只记录时间、Provider、模型、请求阶段、耗时、HTTP 状态码、Provider 错误码、Request ID 和应用归一化错误类型；Provider 错误码与 Request ID 仅在实际返回且通过脱敏校验后记录，不得包含截图、原文、译文、完整请求或响应、API Key、认证请求头。
- 本地诊断日志滚动保留 7 天后自动删除；设置页提供“导出诊断日志”，只在用户主动操作时生成脱敏压缩包。
- 第一版接入 Sparkle 自动更新。
- Sparkle 自动检查默认开启，固定每 6 小时检查一次；设置页只提供自动检查开关，不允许修改检查频率。
- 不自动下载更新，也不提供自动下载开关；发现新版本后由用户显式开始下载。菜单栏与设置页监听同一应用级 Sparkle 状态，只有 Sparkle 确认下载完成后才显示“已下载”。下载完成不打断截图或模型任务，应用退出时安装，也允许用户选择“立即重启并更新”。
- 应用持续不退出时，更新下载完成 7 天后温和提醒一次；菜单栏始终提供“检查更新”。
- 第一版只使用稳定更新通道，不提供 Beta 通道，也不向 Sparkle appcast 发送匿名系统画像。
- appcast 通过 HTTPS 提供；更新包同时使用 Developer ID 签名、Apple 公证和 Sparkle EdDSA 签名。
- 支持登录时启动，默认开启，并允许用户修改。
- 分别提供 Universal、Apple Silicon 和 Intel 三个安装包。
- v1 只发布上述三个 Developer ID DMG 直接分发包，不提交 Mac App Store，也不增加 MAS target、TestFlight 或第四条发行流水线；启用 App Sandbox 是应用安全边界，不代表 v1 采用 MAS 分发。
- Universal、Apple Silicon 和 Intel 构建分别订阅独立的 Sparkle appcast，自动更新保持当前安装包架构，不自动迁移到 Universal 或其他架构。
- 三条 appcast 使用相同版本号和同一 Sparkle 公钥，但分别指向对应架构更新包。
- 只有三个架构的签名、公证、stapling 和 Sparkle 更新签名全部成功后才发布该版本及三条 appcast；任一架构失败则整个版本不发布。
- 安装包使用 Developer ID 签名、公证并 stapling。
