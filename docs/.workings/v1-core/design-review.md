# VLMSnapper v1 核心规格设计审查

审查对象：`docs/specs/v1-core.md`

结论：核心产品行为可以进入实现拆票；两项 Provider 事实仍是发布门槛，不阻止先实现抽象和非 DeepSeek 纵切。

## 审查检查

- [x] 规格使用 `CONTEXT.md` 中的 Provider、模型操作、受管理截图、意外中断、归一化错误等术语。
- [x] 截图路径采用 ADR-0006 的 `~/Pictures/VLMSnapper/`，没有沿用 ADR-0002 被修订的早期路径。
- [x] 用户每次显式操作只有一个网络请求，翻译直接从截图一次返回原文和译文。
- [x] 本地持久化失败、请求失败和最终落库失败的网络边界互不混淆。
- [x] 失败模式按用户操作序列覆盖权限、捕获、选区、保存、请求、流式、取消、崩溃、清理、数据库和更新。
- [x] 自动重试、隐式回退、自动改图、残缺结果持久化均被明确禁止。
- [x] Provider 模型列表刷新、消失模型、图片兼容状态和活动请求期间冻结配置的状态入口与出口完整。
- [x] 受管理截图的显示、上传和删除都要求数据库记录与 SHA-256 匹配。
- [x] 首次引导、操作栏、结果、菜单栏、管理中心和 Provider 配置均有已确认原型方向。
- [x] 测试 seam 覆盖应用工作流、Provider 契约和 macOS/持久化集成，未依赖私有实现细节。
- [x] Out of Scope 明确排除 OCR、本地模型、标注、自动重试、自定义端点与 MAS。

## 审查中修正

1. 将“截图保存”与“历史准备记录”明确拆成两个连续门槛，避免 PNG 已写入但数据库失败时误上传。
2. 明确数据库最终写入失败时的重试只能写数据库，防止重复计费或产生第二次 Provider 请求。
3. 明确 ADR-0006 优先于 ADR-0002 的早期截图路径描述，消除实现依据冲突。
4. 把普通限流与账户额度问题分开，避免把长期额度故障错误限制在 1–5 分钟提示中。
5. 把系统级恢复界面列为实现前窄状态验收项，不在核心原型之外擅自建立第二套信息架构。

## 实现前门槛

- 拆票时必须把应用工作流状态机作为第一个可测试纵切，先建立真实红测再实现。
- DeepSeek 适配器可以实现，但其发布就绪必须等待规格中的真实账户契约测试 Pending 项关闭。
- 数据库恢复、权限撤销和更新安装三类系统交互，在对应纵切实现前补充窄状态原型或系统对话框验收稿。
