# Ticket 23 — 生产应用组合验收改造方案

状态：2026-09-07 用户确认按最小注入方案继续。现有 executable target 导入、Model 纵切、delegate 原生成功/关闭重开/返回路径与验证—冻结互斥已分步验证；完整组合 A/B 的其他分支仍在施工。不拆共享 target，不安装、不发版。

现行行为与长期约束以 `docs/specs/v1-core.md`、CONTEXT 和 ADR 为准。本文件仅记录代码定位、拟议施工顺序与设计审查。

## 1. 目标与范围

补齐两条组合验收：

1. 引导 → 内联 Provider → 原生输入 → 验证一次 → 模型选择 → 保存 → 自动返回；以及关闭、失败和重建恢复分支。
2. 凭据验证/恢复与截图/模型请求/结果重跑的双向互斥，验证被阻止时没有冻结、网络或历史副作用，结束后入口恢复。

不改界面、文案、存储策略、数据库 schema、模型协议、超时、替换规则或截图算法。不引入通用 DI 容器、服务定位器、运行期插件或测试模式开关。

原型门声明：这是无可见变化的构造重构，按 `/to-spec` 的例外不制作新原型；既有确认原型仍是视觉回归依据。若实施发现需要新增提示或改变交互，应停下单独过原型门。项目能力声明启用 zh-Hans/en，因此须回归双语资源；RTL UI 镜像未启用，该项跳过。

## 3. 推荐结构

保留现有 `VLMSnapperApp` executable target、源码位置和 `main.swift`。临时导入探针已在 Xcode Swift 6.2 上编译、链接并运行两个测试，原入口无需改成 `@main`。新增 `VLMSnapperAppTests` 直接依赖 App；不增加共享 target 或 library product。

应用 target 继续使用现有 Core、UI、Sparkle targets；UI 本地化资源不搬迁。内部状态继续私有，不为测试公开 setter。先通过 Model 正式回调验证构造纵切，后续才接通 delegate、实际窗口和原生控件；前者不抵扣后者。

构造依赖是显式、带类型的一组值，不是按字符串查找的容器。正式工厂只能产生真实 adapter；隔离测试构造必须显式给齐相关依赖，不能在漏传时悄悄回退到真实网络、真实 Keychain 或标准目录。

### 依赖清单

| 外部交互 | 正式装配 | 测试装配 / 保留部分 |
|---|---|---|
| 模型列表 HTTP | 现有 URLSession loader | `ProviderHTTPDataLoading` 控制响应/延迟；保留 OfficialProviderModelLister |
| 图片 HTTP 流 | 现有 URLSession streamer | `ProviderHTTPStreaming` 返回录制协议形态；保留请求构造、executor、解析和错误归一化 |
| 凭据 | AppleKeychainProviderCredentialStore | 测试 target 的隔离 store；同一对象供配置与图片请求使用 |
| Provider 元数据/历史/图片 | 现有生产路径 | 同样的文件与 SQLite 实现，换成每例独立临时目录；存储故障优先用真实文件条件制造 |
| 语言/权限记录/登录项偏好/保留期 | 现有 UserDefaults | 所有包装器使用同一独立 suite；禁止漏用 `.standard` |
| 权限与冻结 | CoreGraphics / ScreenCaptureKit | 复用现有授权、检查和冻结 interface，给固定图像/可控完成；保留冻结协调与原生遮罩 |
| 登录项 | 现有 SMAppService adapter | 复用 LoginItemServicing，记录操作但不修改系统 |
| 更新 | 现有 Sparkle driver 与事件绑定 | 复用 UpdateDriving，控制事件；保留 UpdateLifecycleCoordinator |
| 快捷键 | 现有 Carbon backend | 复用 GlobalShortcutRegistrationBackend，触发它实际注册的 handler；不抢真实快捷键 |
| 单实例 | 现有 POSIX 锁与分布式通知 | 真实临时锁；隔离的 PrimaryInstanceMessaging，不唤醒已安装 App |

这些启动隔离项是运行真实 `start()` 的必要条件，不是顺手改造其他功能。无需 mock 自有 coordinator，也不加 `isTesting` 去跳过恢复、保存、互斥或启动顺序。若仍有未列出的系统调用会在测试路径触发，先补进隔离清单并审查，不能默认放行。

### 生命周期不变量

- 获得主实例资格后才装配 model、打开数据库、注册快捷键或启动更新；创建依赖配置本身不能提前触发这些操作。
- 一个主实例只有一份 Provider 配置协调器和活动所有权状态；所有窗口使用它们。
- 关闭管理中心仅结束窗口草稿；已提交作业仍由应用持有。正常退出的取消、等待、保存和返回结果遵循原逻辑。
- UI 操作仍在 MainActor，外部异步 adapter 遵循既有 Sendable/actor 约束；不通过额外 detached task 或锁掩盖编译错误。
- 测试退出必须停止观察/清理任务、释放窗口与注册。若当前释放接口不足，只补必要的明确关闭 interface，走生产清理代码，不借测试直接清内部字典。

## 4. 测试如何穿透

### 组合 A：引导到配置完成

使用原生引导按钮打开实际管理窗口；原生字段输入非秘密样本，分别走菜单 Paste、Return 和验证按钮。外部 HTTP adapter 暂停后记录确切请求，重复操作不增加提交；释放响应后观察模型控件，未选择时引导不自动返回。通过实际模型控件选择，确认原生管理窗口退下、引导重新可见、配置已保存。

失败支路覆盖：非法输入、验证失败、写入失败、验证中切卡片/关闭、提前关闭返回、普通设置入口不返回引导、成功回调迟到不重复返回。保持已有精确 Key 和无回退约束。

重建时销毁旧 model/editor/session，再使用保留的测试凭据状态与临时磁盘构建全新应用对象；验证已保存配置可读，或写 Key 后元数据失败时恢复真实模型列表并发布状态。不能复用旧 coordinator 冒充恢复。该用例不是 OS 进程崩溃或真正 Keychain 持久性证明。

### 组合 B：双向互斥与状态保存

从实际 UI 开始验证/恢复并暂停其外部完成；从已注册快捷键 handler、真实菜单按钮和结果 Try Again 触发操作。观察当前 Provider 卡片、原生窗口状态和外部冻结/模型请求次数；用真实历史公开查询比较前后内容，确认被阻止时无新增或覆盖。

反向通过真实入口开始冻结/选区/模型请求，再尝试提交配置、触发恢复；配置提交拒绝，恢复等待，原选区、结果和另一 Provider 草稿保持。成功、失败、取消结束后验证入口恢复；包括选区转模型请求没有可插入配置作业的空档，以及旧完成不能释放新作业。

未保存结果状态优先通过真实临时存储失败产生，再尝试截图，验证没有冻结且现有结果被请求显示；不直写 workspace 私有字段。物理前台效果仍由人工验收。

等待使用可控 continuation 与带截止时间的可观察终态等待；不靠固定 sleep 假定完成。挂起作业必须在 finally/defer 中可释放并结束；断言失败也不能留下长驻进程。

## 5. 实施顺序与门禁

1. **基线**：记录主线版本、目标图、现有测试和正式资源/身份基线，不接触已安装 App。
2. **直接引用 App target**：已通过临时探针验证；在既有 target 内增加构造参数，不搬应用实现，不扩大成员可见性。
3. **一条 Provider 纵切**：传入 HTTP/凭据/隔离存储及启动所需 adapter，加入组合 A；不批量重写内部会话。
4. **一条互斥纵切**：接入同一应用的冻结/模型请求入口，加入组合 B 和相关终结支路。
5. **检验测试有效性**：既有行为可能首跑就绿，应明确记作补充回归；用经批准的窄变异或真实失败输入证实断言敏感，不编造红先于绿。不得削弱安全门禁来制造假红。
6. **收尾**：严格构建、全套测试、58 行 gate、本地化与资源检查、代码 review、测试 review，再执行全 feature 三阶段文档回归。
7. **正式产物独立验收**：确认 executable/Bundle ID/Keychain service/profile/entitlements/资源保持，目标依赖图不包含测试实现；签名安装版的 Keychain 与物理快捷键/前台操作分开记录。需要安装或真实账户操作时单独取得授权。

## 6. 不得混淆的证据

| 能证明什么 | 不能替代什么 |
|---|---|
| 原生程序化输入到同一生产接线的完整结果 | 实际键盘快捷键被 macOS 送达 |
| 窗口已显示/隐藏、内容正确 | macOS 实际前台焦点与遮挡情况 |
| HTTP 协议 fixture 通过真实解析 | 真实账号、真实网络服务当前可用 |
| 重建应用对象后配置恢复 | OS 崩溃、进程强杀、签名 Keychain 授权 |
| 本地构建与结构门禁通过 | 正式签名、公证、安装验收或整个收口票已完成 |
