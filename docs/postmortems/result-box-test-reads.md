# 结果框测试读不到失败，以及原生测试被环境打断

背景：ADR-0015 把模型结果移到截图界面（v1-core::REQ-010–014）。下列问题都在合并前发现，没有进入发布版本。

## 1. 按钮按下后的读取不可能失败

### 故障

`copyAndSaveWaitForARunningRequest` 断言请求进行中按复制和保存没有动作。去掉“告诉操作栏请求正在进行”的那一行，它照样通过。

### 已复现的因果链

操作栏的按钮动作在主 actor 的 `Task` 里执行。`@MainActor` 测试只在下一次挂起时才让它运行，泵一次运行循环不够（2026-11-03 在独立程序中实测：`Task` 经 5 次运行循环后仍未运行，一次 `await Task.yield()` 后已运行）。所以按下后立刻读，读到的总是动作发生之前的状态。

### 为什么此前没发现

这条断言长得像真实测量，运行也一直是绿的；第一轮代码自审和用例设计审查都没有问“它在什么情况下会红”。独立的实现后复核逐项回答这个问题时才发现。

### 新增防线与证据边界

`clickExtract`、`clickTranslate` 等到动作任务运行之后才返回，其余按压在读取前显式让出。项目 `AGENTS.md` 写明这条约束。复核之后，新断言逐条用“破坏行为再恢复”的办法确认过会失败，记录在本次施工记录里，但没有门禁自动发现新的同类写法。

## 2. 原生窗口测试在锁屏和切换应用时失败

### 故障

连没改过的截图测试也因操作栏不出现而超时；`native-paste` 等不到键盘窗口；`alertIsSheetOfOverlay` 的遮罩没有键盘焦点。

### 因果链

- **锁屏（已证实）**：2026-11-03 超时时 `CGSSessionScreenIsLocked` 为 1，解锁后同一批测试通过。
- **切换应用（部分证实）**：`native-paste` 失败时的轨迹显示前台进程切到了其他应用。`alertIsSheetOfOverlay` 的失败没有记录前台状态，归因于操作屏幕来自用户的说明，没有在无人操作时对照。

### 为什么此前没发现

这些测试通常在无人操作时运行，失败又像偶发。CI 的托管运行器没有人在操作，碰不到这个原因。

### 新增防线与证据边界

项目 `AGENTS.md` 和 `docs/ops/provider-regression.md` 写明运行时不要操作电脑或锁屏。这是靠人守的约定，没有门禁。如果 `alertIsSheetOfOverlay` 在无人操作时仍失败，上面的归因就不成立，应记录 `NSApp.isActive` 和键盘窗口后重查。
